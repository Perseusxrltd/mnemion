# Organization recovery directory and independent kit

This batch advances A06, A07, A09 and A12 in the full continuity contract. It does
not replace the required delegated host controls, company identity onboarding,
recovery-custodian policy, replication or safe failover.

- An organization administrator records primary/recovery/ingestion hosts,
  independent operator-console addresses, recovery contacts and material locations.
  The directory distinguishes complete database backups, access/deletion ledgers
  and source mirrors. A reported verification time is explicitly human-reported.
- Metadata stays outside memories, source ingestion, embeddings and automatic
  retrieval/librarian context. An explicitly authorized administrator agent can
  read the directory through its reviewed operation.
  The service enforces current administrator authority, tenant isolation, bounded
  content, optimistic concurrency and an audit event. It never copies saved login
  credentials into the directory or executes an entry as a command. Free-text
  references are not a credential store; provider sign-in stays independent.
- Enrolled desktop administrators retain a protected, destination/identity-bound
  dated copy. Reconnection refreshes it; current non-administrator observations
  remove it. An offline copy describes earlier state and cannot authorize writes.
- A downloadable encrypted HTML recovery kit opens locally or on independently
  owned HTTPS hosting without Mnemion or its original agent. Encryption happens
  locally with a separately held passphrase. The kit contains references, not API
  keys, passwords, a database backup or a replica. Viewing it makes no requests.
- App, HTTP, SDK and the reviewed agent catalog expose the same directory controls.
  Existing installations and connections remain usable without configuring it.

Acceptance includes two independent administrators, a restricted agent and a
different tenant; a conflicting update and revoked administrator; real database
backup/restore; protected desktop caching with an offline server and changed
membership; browser configuration/export and offline decryption; ciphertext
tampering, wrong passwords and malicious data; preservation of old connection
formats; and the normal native installation/update gates. Source-only evidence
must remain separate from released and live-provider acceptance.
