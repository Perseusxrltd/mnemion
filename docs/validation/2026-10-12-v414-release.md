## Original shared host

The adopted original host updated **4.0.13 → 4.0.14 at 02:14:24 UTC** through
an explicit operator check/stage/apply of the published signed patch. Automatic
updates remain enabled. This particular cutover was requested by the operator;
the preceding [4.0.12 → 4.0.13 unattended patch](2026-10-12-v413-release.md)
is the separate evidence for automatic host updating.

At **02:16:31 UTC**, the active signed 4.0.14 runtime and every pre-update backup
member were independently reverified. The backup was **50,275,322 bytes**.
Tenant, principal and API-key table digests stayed identical; all **ten** grant
members, roles and scopes matched its backup ledger, with no renewed grant
timestamps in this check. The public address remained unchanged. No database
backup was restored and no owner database login entered the API, worker or
updater child environment.

The corrected runtime accepted its actual child receipts while a separate
read-only observer shifted the reported process creation epoch by **1,304
seconds**. Readiness and process identities remained valid before, during and
after that observation. The system clock, live processes and receipt files were
not modified by the check. This verifies the
[reproduced clock correction](2026-10-12-host-clock-readiness.md); it does not
prevent a hosting provider from suspending a computer or its network.

At **02:18:45 UTC**, the actual Windows app refreshed the server version through
its normal Setup screen while retaining the saved human administrator. It
reported desktop **4.0.13** and workspace server **4.0.14** separately, with no
credential entry, memory writes or model calls. Background operation, login
startup and automatic desktop updates remained enabled. No desktop replacement
is claimed for this server-only check.
