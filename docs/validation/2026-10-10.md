# Release validation — 10 October 2026

The product remains in release validation. These are measured results from an
isolated fixture, not a production capacity or universal compatibility guarantee.
The [implementation ledger](../implementation/v4_progress.md) tracks remaining
release requirements. Private logs, credentials, databases and downloaded model
weights are outside the repository in persistent validation storage.

## Retrieval

The [frozen plan](../../benchmarks/plans/longmemeval-v4.json) uses 12 development
questions and 48 held-out questions from the MIT-licensed LongMemEval cleaned
dataset. The held-out split contains 45 answerable questions and 3 abstention
cases. All historical sessions and roles are ingested; question text and reference
answers are excluded from ingestion. Each question has its own authorized space.
All records finish indexing before scoring. The public
[aggregate results](retrieval-2026-10-10.json) include dataset, plan, evaluator and
result hashes, category results and bootstrap intervals.

| Mode | Recall@5 | Recall@10 | Recall@20 | nDCG@20 | MRR@20 | Complete evidence in compact context |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Hybrid | 89.07% | 95.74% | 100% | 0.9111 | 0.8882 | 42/45 |
| Semantic | 92.78% | 99.44% | 100% | 0.9248 | 0.9134 | 44/45 |
| Lexical | 6.67% | 6.67% | 6.67% | 0.0717 | 0.0889 | 2/45 |

These are **session-level evidence metrics**. Finding a labeled conversation does
not prove that a retrieved excerpt contains the answer or that a model will answer
correctly. Compact context is limited to 4,096 E5 tokens. For the 45/45 complete
evidence result at 20, a Wilson 95% interval is approximately 92.1–100%; the
all-one bootstrap interval is not evidence of universal accuracy. Abstention
cases are excluded from recall and retained for separate answering evaluation.

Semantic retrieval performed better at small cutoffs in this sample. Lexical
search uses strict full-text query terms, which performs poorly on long natural
language questions. It remains useful for exact words and filters; this evaluation
does not justify presenting it as an equivalent natural-language fallback. The
frozen evaluation predates a later source-eligibility SQL join optimization,
covered separately by retrieval and deletion regression tests. Scoring and fusion
were unchanged; the historical timings below are not measurements of the final
release tree. Further query/fusion work needs a new declared development and evaluation split.

Hybrid top-20 requests had p50 172 ms and p95 290 ms; semantic had 131/200 ms and
lexical 23/45 ms. These are sequential request measurements, with modes run in
that order, on an Intel Core Ultra 7 155H exposed as 22 logical CPUs to WSL with
7.47 GiB RAM and 2 GiB swap. Builds and native applications shared the host, and
cache state differed between modes. These timings are not a controlled throughput
comparison or the proposed 100,000-record concurrent workload test.

The held-out run first exceeded its declared 1,800-second indexing budget before
scoring any question. A separately identified continuation reused the exact
ingestion receipts and unchanged retrieval configuration with a 7,200-second
budget. The failure remains recorded; the continuation's wait time must not be
reported as the complete ingestion time. Two local E5 workers used two threads
each. The corpus contains 2,287 held-out records plus 590 development records.

Answering is a separate evaluation of the saved context with a pinned local
Qwen3-4B Q4_K_M model, a fixed evidence-only prompt, citation numbers and explicit
abstention. Two development responses completed before a local memory exhaustion
interrupted the run; no held-out answers completed. Kernel logs identified the
local `llama-server` process as an OOM victim. Heavy answering evaluation has been
stopped on this machine and must move to an adequately sized separate runner.
Local checks now run sequentially under a 2 GiB process-group limit with no swap
and a two-core CPU quota. No answering accuracy claim is made here.

## Native Obsidian and desktop

Obsidian 1.14.4 ran against an isolated vault. In Reading view, hostile HTML,
script tags, Dataview code fences and template openers displayed as exact literal
evidence. No remote image or script element appeared, and the script marker was
not executed. A native display issue with escaped parentheses in link labels was
fixed and rechecked.

After a correction and deletion, the refresh preserved the memory's path, a
personal annotation, an unmanaged note and settings. Three obsolete managed files
were pruned; a second refresh made no additional deletion and reported no
conflicts. The final vault resolved 29 links, including the unmanaged link-format
fixture, and retained three source anchors. A copied-v3-vault migration and final
native graph acceptance remain separate release checks.

The Linux x64 build produced a 142,415,604-byte AppImage and a 114,322,536-byte
Debian package. Payload checks and a real packaged window passed: the workspace,
sandboxed bridge, tray icon and local vault client loaded, and Node was unavailable
to the renderer. These artifacts precede the additional native Python license
collection and require regeneration before distribution. Final Windows, macOS,
ARM64 and publisher-signing gates remain open.

## Security and redistribution

The default Python production environment had no known advisories among 58
third-party distributions at the recorded audit. Eight moderate Electron build
dependency findings trace to `sprintf-js`; no high or critical finding was
reported. The packaged application ASAR contained only the three compiled bridge
files and package metadata, with none of the affected build dependency chain.
The [security review](../../security_best_practices_report.md) records exposure and
the remaining release checks.

Desktop and container builds collect original license texts and package-level
CycloneDX inventories. Additional native notices now cover the exact locally used
standalone Python binary, including libraries embedded inside `libpython`.
Unknown embedded runtimes fail collection rather than inheriting unverified
notices. The inventory is not a full operating-system composition scan.

Retained scans found no secrets in Git history or the reviewed source snapshot.
A final scan of the publication tree and final artifacts is still required.
GitHub private vulnerability reporting is enabled. No release has been published.
