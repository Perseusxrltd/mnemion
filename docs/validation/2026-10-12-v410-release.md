## Original shared workspace

The exact signed final runtime passed an isolated restoration/migration
rehearsal on the original host at **06:24:43 UTC**. It preserved all 50 existing
data-table hashes, recovery-administrator access and revoked copied credentials.
A temporary restricted contributor passed save/index/withdraw/purge/replay,
API/MCP diagnostics and clean shutdown. This made no production memory writes
or cloud model calls.

The live service remained healthy on **4.0.14**, last directly observed at
**08:05:32 UTC** through the independent Windows administrator. Reloading the
provider's desktop app restored verified terminal control. The operator journal
confirmed no migration had started; the original encrypted backup was preserved
and a new one created. Windows decrypted and verified that new backup at
**07:45:49 UTC**, without writing plaintext recovery material. Windows then
locked before the migration command could be staged. The fifteen-minute
freshness preflight expired during this interruption, and must be satisfied
with another preserved, verified backup before migration.

Separately, the [actual Windows installation automatically updated and
relaunched on 4.1.0](2026-10-12-windows-v410-auto-update.md), retaining its update,
background and startup settings. The protected independent administrator
connection remained valid after the update.

Inspect the operator journal before retrying; do not assume a command sent
while the remote console was disconnected executed. Preserve the original host,
its keys and space grants. The prepared Windows lab will reduce only its own
restricted test identity to contributor after confirming server 4.1.0, then
exercise author withdrawal without changing the selected human-administrator
connection. That live deployment acceptance remains pending.

Compatible managed service patches deliberately do not cross this minor/schema
boundary. A published desktop update does not migrate a separately hosted
workspace. Public availability follows the user's request to ship verified
targets while continuing separate host/deployment acceptance.
