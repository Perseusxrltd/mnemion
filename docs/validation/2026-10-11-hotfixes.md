### First 4.0.8 release run and corrections

Run `38107521528` passed all six native desktop installation/update gates, both
Linux containers, Studio, dependency audit and the Linux service matrix. The
release remained unpublished because the legacy coverage denominator included
the separately tested service, the Apple-silicon process assertion expected a
venv executable rather than Python's framework launcher, and Intel service
staging correctly refused to compile a missing upstream cryptography wheel.

The legacy suite now measures only the retained implementation with a 45% gate;
its 311 tests passed with **49.07% coverage**. Service coverage retains its separate
75% gate. Runtime assertions verify the actual isolated module, candidate working
directory, permitted native Python executable and served candidate OpenAPI
version, including restoration of the previous version after rollback.

Upstream cryptography 50.0.2 no longer ships Intel Mac wheels. Older available
Intel wheels reported advisories and were not selected. The new free native
builder uses the locked 50.0.2 source and OpenSSL **3.5.9**, verified against
SHA-256 `603f5602e2eef00d77fbd429d34dcd5822bb301757a1bc9cdb24c670f1eb859a`.
The static wheel includes licenses/provenance and becomes a separately signed
manifest entry; other platforms do not download it. Native execution, static
linkage inspection, managed installation/rollback and the dependency audit are
mandatory before publication. Local protocol/update checks passed **87 tests**
in 64.53 seconds after adding the wheel validation and platform-aware assertions.
These local tests do not establish native Intel compilation success.

The subsequent native run compiled cryptography successfully with static
OpenSSL. It produced the upstream Python 3.12 stable-ABI wheel; the initial
packaging check incorrectly expected a Python 3.11 tag. The builder, signed
manifest policy and installation guide now require the actual
`cp312-abi3-macosx_11_0_x86_64` tag, consistent with Mnemion's Python 3.12 minimum.
The 16 dependency-wheel policy tests passed after that correction. The complete
native install/update/rollback gate remains required for the fresh release run.

The next native gate identified a dependency-inspection error: `otool -L` also
lists a dylib's own `LC_ID_DYLIB` name. The check now corroborates that first name
with `otool -D` before excluding it, then rejects every non-system dependency,
including a second entry with the same name. The build provenance records the
actual dynamic dependencies. Inspection of the hash-verified upstream ARM wheel
independently confirmed this load-command distinction. The 27 native-builder and
signed-wheel tests passed, including Homebrew/rpath and inconsistent-output
rejections; native Intel execution remains a separate release gate.

Issues **19** and **20** were reproduced against the pre-fix code: four cursor
type cases raised `AttributeError` and a colliding librarian key raised PostgreSQL
`UniqueViolation`. The corrected pagination, librarian, transaction, evaluation
and connector suite passed **76 tests** in 25.28 seconds. Malformed UUID fields
now return HTTP 422/`invalid_cursor` across four list routes without exposing the
cursor; invalid service cursors open no pagination transaction. Atomic librarian
accept/undo now own one outer receipt, replay successfully with formerly colliding
keys and preserve exactly three revisions across creation, accept and undo.
