# Hotfix and automatic-update validation, 11 October 2026

This extends the [4.0.3 validation](2026-10-11.md). Results distinguish built
artifacts, actual public upgrades and local candidate checks.

## Published 4.0.4

[Release 4.0.4](https://github.com/Perseusxrltd/mnemion/releases/tag/v4.0.4)
was published at 23:17 UTC on 10 October (11 October in Paris), from commit
`139ff2b3f867ca0c32ef9b854777a83d614fac74` after
[every native and product gate passed](https://github.com/Perseusxrltd/mnemion/actions/runs/38093588260).

- All six native targets passed installation/application checks. Windows x64
  and ARM64 additionally installed an authenticated update and relaunched;
  both Macs passed the packaged updater and restart guards.
- Python 3.12 passed 239 service tests with two skips; 3.13 and 3.14 each passed
  237 with four skips. The 3.12 job enables the real pinned local-model checks;
  platform/optional legacy checks account for remaining skips.
- Windows ARM64 passed 72 client checks with one platform skip. The native
  private-output tests exercised its protected Windows file permissions.
- All 36 uploaded asset digests matched `SHA256SUMS.txt`. Its SHA-256 is
  `2a84188c9a57c893a23fea55b7fa4ad653cad2e152400d853855a6a70b5603ab`.
  Both downloaded Windows manifests/installers passed independent verification.
- The built wheel contains the 81-operation contract and `mnemion-control`
  entry point. The extracted wheel/source package passed a 10.90 MB secret scan
  with no findings. The inventory and archive structure were checked separately.
- All six public primary download URLs returned HTTP 200 with the exact uploaded
  length. The live Perseus XR page automatically selected 4.0.4, including the
  ARM64 Windows download. Both release-triggered metadata workflows succeeded;
  no website edit or redeployment was used.

and normal inactivity/restart guards. The [machine-readable results](2026-10-11-public-upgrades-4.0.4.json)

Durations include the observed check/download/inactivity wait and are not update

disposable runners. No physical reboot or every-OS-version certification is
implied. No main process was launched with `--no-sandbox`; no guard, key, feed or
application entry point was replaced for these observations.

## 4.0.5 source-sync checks

- The full local service group passed **243 tests**, with two opt-in model tests
  skipped and **86.03% service coverage**, before the last acknowledgement-loss
  case. The final focused source/runner/agent group passed **16 tests**, including
  loss before and after an acknowledgement transaction commits.
- Tests use real PostgreSQL and restricted identities. Competing requests cannot
  consume the same expected generation; a request arriving during a scan remains
  pending. Failed scans and future acknowledgements do not clear pending work.
- A real local Git repository was committed, ingested, changed by a deletion,
  requested and scanned again. The removed memory disappeared and the removal
  count was correct. Existing incomplete-inventory and recovery tests passed.
- All seven TypeScript SDK checks and the production Studio build passed.
  In a browser with isolated PostgreSQL and synthetic notes, **Sync now** caused
  the runner to remove a withdrawn note, display one removal/one unchanged item
  and clear the pending request. The result card was visually inspected.
- An explicitly mocked older-server 404 response displayed upgrade guidance
  without an application error banner or an unsupported button. Its expected
  network 404 is not an unexplained browser error. The 390-pixel layout did not
  overflow the document.

Migration 012 and rollback restrictions are documented in the
[patch notes](../releases/4.0.5.md).

## 4.0.6 web installation checks

- The full local service group passed **245 tests**, with two opt-in model skips
  and **84.91% coverage**, before the final container-entry-point correction.
  The final deployment/web group then passed **eight tests**, including the
  actual API entry point with real PostgreSQL, model-preflight failure and
  continued HTTP authentication. Model preparation in that control-flow test
  uses a deterministic fixture; it is not a new model-quality measurement.
- Web bundle and release-artifact checks passed **33 tests**. They cover missing
  builds, modified assets, version mismatch, unsafe paths, license omissions,
  failed replacement, concurrent builders and Windows npm paths.
- The source CLI built the SDK, frontend and **123-component license inventory**.
  Both actual Python formats contained identical Studio files. The measured
  candidate contained 230 files including the manifest, totaling 5,127,576 bytes;
  final documentation edits can change these counts and hashes.
- The wheel was installed into an isolated target outside the repository and
  served using Python isolated mode with a disposable PostgreSQL database. Its
  module and UI resolved from the installed package, with no source checkout or
  Node dependency at runtime. The initial connection page's help link opened
  the guide library, and the 4.0.6 notes rendered correctly. The screenshot was
  visually inspected; the 390-pixel view had no document overflow and browser
  console checks reported no errors or warnings. Readiness returned 200 and
  unauthenticated `/v1/me` returned 401.
- The installed wheel passed a **7.31 MB** secret scan with no findings under
  the existing reviewed rules.
- Container build review found both missing Markdown inputs and a reference to
  a removed model helper. The patch includes the guides, uses the maintained
  offline preparation command and adds Linux x64/ARM64 image-build checks to CI.
  Local passwordless sudo was unavailable, so container-image execution is a
  CI gate, not a claimed local result.

These candidate results accompany the release's mandatory product and native
checks; publication and actual public upgrades are recorded separately.
