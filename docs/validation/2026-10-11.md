# Mnemion 4.0.3 validation

Recorded on 11 October in Europe/Paris; workflow timestamps use UTC. Earlier
release, retrieval and migration evidence remains in the
[10 October report](2026-10-10.md). Counts below apply only to the named checks.

## Windows ARM64

[Native ARM run 38087726926](https://github.com/Perseusxrltd/mnemion/actions/runs/38087726926)
passed first NSIS installation, an independently signed private 4.0.2 → 4.0.3
upgrade and automatic relaunch. Sixty-eight packaged binary hashes matched
before/after. Installation paths included spaces; cancellation, tampering,
interruption and restart guards were exercised. The
[full six-target run](https://github.com/Perseusxrltd/mnemion/actions/runs/38087726923)
also passed on the same installer-fix commit.

The fix is confined to the ARM NSIS running-application check: use native
`Sysnative` PowerShell/cmd paths before the upstream check. It retains the
upstream shutdown safeguards. These are native private-fixture results, not a
previous public ARM upgrade: 4.0.3 introduces that architecture's first public
installer. Publication requires the complete release matrix to pass again.

Windows x64 separately passed a public, unmodified 4.0.1 → 4.0.2 automatic upgrade
through the official feed with preserved settings in 112.17 seconds. See
[the original evidence](2026-10-10.md#published-402-and-first-public-windows-upgrade).

## Local model memory

The new [resource probe](../../benchmarks/local_model_resources.py) uses one
59,220-character synthetic English/French document, 11,521 E5 tokens and 35
chunks, plus one query. Both runs used the same cached pinned model, Python
3.12.3, FastEmbed 0.9.0, ONNX Runtime 1.31.0 and Tokenizers 0.23.3 on Linux x86_64
under WSL2. Each fresh process had a **2 GiB cgroup memory cap**, no swap, a
**two-CPU quota** and two model threads; the runs were sequential.

The baseline uses immutable release commit
`9229945a415153abfad6d3c57e762f2140904f68`; the candidate changes tokenizer
allocation/locking. No model weights, prefixes, batching, generation, chunking
or normalization settings change. The same benchmark script measures both.
Machine-readable inputs, runtime identities and results are in
[the comparison JSON](2026-10-11-model-memory.json).

| Metric | 4.0.2 | Shared tokenizer |
| --- | ---: | ---: |
| RSS after model preparation | 788.4 MiB | 492.4 MiB |
| RSS after document embedding | 1342.9 MiB | 1059.1 MiB |
| Process peak RSS | 1342.9 MiB | 1059.3 MiB |
| Model preparation | 2.6918 s | 1.5299 s |
| One query | 0.0062 s | 0.0065 s |
| One 35-chunk document | 4.7006 s | 4.5939 s |

All vectors and source spans had the **same output SHA-256**. The focused
acceptance group passed **19 tests** in 10.15 seconds: real pinned E5/BGE source
semantics, special tokens, Unicode offsets, long documents, PostgreSQL semantic
retrieval, tokenizer restoration after errors and concurrent admission/counting.

This is one controlled measurement per implementation, not a held-out quality
score, bandwidth benchmark, RAM guarantee or concurrent production load test.
Separate API/worker caches remain; peak allocation varies with document shape
and retained ONNX pools. Issue 13 therefore remains open. A smaller-batch
experiment changed quantized vectors, and disabling the ONNX arena increased
latency; neither behavior is silently enabled by this patch.

## Public update observation

Both Mac architectures **passed** the unmodified public 4.0.1 → 4.0.2 upgrade
in [run 38089665208](https://github.com/Perseusxrltd/mnemion/actions/runs/38089665208):
Intel in **164.03 seconds**, Apple silicon in **288.69 seconds**. The original
processes exited with code zero; new 4.0.2 processes remained alive, the default
preferences and profile sentinel survived, and the replaced bundles passed
strict/deep code-signature verification. The runners were already idle before
launch; these durations do not replace the ten-minute system-inactivity policy.
The apps used their embedded production key and official feed, with no modified
entry point, debugger, simulated idle time or signing override. Login registration
was disabled for these disposable runners, so this is not a boot-startup test.

The first public Mac run observed a replacement 4.0.2 process but incorrectly
treated the exited, unreaped launcher PID as a still-running old application.
The first Linux checks depended on process environment/executable information
that changes during AppImage exec. The observer now reaps its POSIX child and
uses the newly created default Linux profile's lock plus its mounted archive.

Neither correction changes the shipped app or bypasses its timers, safeguards,
production signing keys or feeds. Linux verification continues separately; it
must also prove the installed AppImage matches the public target's checksum.
The earlier Linux runner had Xvfb without a window manager, so it could not
honor the app's background minimize/focus requests. The rehearsal now starts
Openbox and waits for real window-manager registration before launching the
unmodified application. Inactivity and focus guards remain unchanged; external
X11 state and the update-cache inventory are retained for failure diagnosis.

## Remaining release limits

Local acceptance on release commit `ffab0705c6a7315700e12a919de03c2721d433bc`
passed **227 service tests**, with two opt-in model tests skipped in that run and
**85.70% service coverage**. The separate 19-test real-model group above covers
those models. Client checks passed 69 tests with one platform skip; desktop
update checks passed 23 tests and the TypeScript SDK passed seven. Studio's
production build includes the new offline release notes and validation guide.
Ruff, release metadata/lockfile consistency and the committed-change secret scan
also passed. The release workflow repeats the native and product gates before
assembling a draft; successful local checks alone do not publish artifacts.

SignPath publisher approval is pending. Mac first-install approval, managed OS
policies, broader OS-version coverage and boot startup need their own evidence.
Desktop upgrades do not upgrade a separately deployed memory server. Hosted
OAuth, server supervision/updates, further memory reductions and source/retrieval
improvements stay on the [roadmap](../ROADMAP.md).
