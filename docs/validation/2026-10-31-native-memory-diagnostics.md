These are developer diagnostic prototypes. The standalone Windows SDK measurement, native Windows ctypes declaration comparison, and corrected macOS helper and Linux BPF builds have passed. The first macOS and Linux compilation failures remain recorded. These results do not close product issues or qualify application resource budgets.

**Windows SDK.** [Run 41237380248](https://github.com/Perseusxrltd/mnemion/actions/runs/41237380248) measured identical SDK layouts on native x64 and ARM64, apart from the architecture identifier. Expanded [run 41244785682](https://github.com/Perseusxrltd/mnemion/actions/runs/41244785682), source `f49ab34923d018efb3d2d30beb3a954aa6b73a48`, passed on both targets, preserving the nine original records and adding five matching layouts. The extended item is 16 bytes, with `ExtType` at offset 2 and combined bitfield storage at offset 4 spanning 2 bytes; its SDK masks are 1 and 65,534. This is an SDK experiment, not a provider bitfield-value match. The [SDK validation note](2026-10-31-windows-sdk-abi.md) retains both sets of original JSON and the earlier failures, including `C4244` and `C4310` during expansion. The [standalone tool](../../deploy/windows_sdk_abi/README.md) supplies measured C layouts. The first native ctypes declaration comparison then passed on both targets in [run 41248868407](https://github.com/Perseusxrltd/mnemion/actions/runs/41248868407), source `7a7ee629e9be09f91aad79b311c885372a6993fb`: 14 structure sizes and 137/137 addressable fields matched, with no missing layouts or mismatches. Both receipts record zero additional provider library loads, `native_api_loaded=false`, and false tracing/emission/resource-acceptance flags. The SDK validation note links the reviewed original declaration receipts. Controlled ETW emission, owned cleanup and lifetime/counter correctness remain separate gates.
