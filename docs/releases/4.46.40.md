# Mnemion 4.46.40

Classic CLI model controls now stop only a process Mnemion launched and its
verified children. Private launch records let a later local command manage the
same model without targeting unrelated servers by executable name. Automatic
idle stopping and restart defer while recorded requests are active; an explicit
stop is retained and cannot be undone by an automatic restart.

`mnemion llm stop` also handles an unresponsive owned model. Unverified shutdown,
failed startup and failed model tests now return nonzero exit codes so agents
can detect failure. `llm test` succeeds only for the requested `MNEMION_OK`
reply. Windows PowerShell/executable and WSL script paths are passed as separate
arguments. WSL scripts remain unchanged; guest shutdown still requires the
original guest process manager. The [management guide](../guides/llm-backend-management.md)
explains foreground scripts, ownership, exit codes and the remaining limits.

The telemetry collector now verifies Linux core-dump suppression before opening
its listener or reading collection state. Production product collection remains
**disabled** while resource, privacy, deployment and platform acceptance continues.

The [model-control validation](../validation/2026-10-27-managed-model-custody.md)
and [collector validation](../validation/2026-10-27-telemetry-crash-boundary.md)
record the source evidence and qualification limits. Native process checks now
run in the existing release matrix. Published downloads and platform results
remain in the automatically maintained [release status](../RELEASE_STATUS.md);
the [roadmap](../ROADMAP.md) retains the full outstanding scope.
