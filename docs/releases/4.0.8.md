# Mnemion 4.0.8

This patch brings Studio into the Perseus XR visual style and adds independently
signed automatic service patches for explicitly adopted Linux/macOS hosts.
All six desktop OS/architecture targets and their existing update feeds are retained.

## Changes

- Unify workspace, navigation, settings, insights/evaluations, documentation and
  local-vault surfaces with the website's ink, ivory and gold palette. Bundle
  Inter/Outfit and their licenses locally, retain distinct chart series, add
  grouped responsive navigation and derive the displayed patch version from
  package metadata. See the [design system](../STUDIO_DESIGN.md).
- Give already-open web tabs a reload recovery screen if a service hotfix
  replaces a lazily loaded screen bundle. Keep navigation available and require
  an explicit reload, with a reminder about unsaved text and the connection.
- Add `mnemion-service updates` for local operator/agent setup, status, checking,
  staging, application and pause/resume. Managed instances enable stable checks
  by default and supervise API, worker and updater without systemd.
- Authenticate the exact wheel, source archive, dependency lock and migration
  inventory with a separate Ed25519 release signature. Reject older or changed
  immutable releases, unsafe archives and changed installed application bytes.
- Stage locked dependencies in an isolated environment without source builds or
  Python downloads. Automatic cutover requires the same major/minor version,
  migrations and embedding generations.
- Supply the current cryptography library for Intel Macs with statically linked,
  pinned OpenSSL, its licenses and source provenance. The release signature binds
  that wheel; managed updates check its identity against the dependency lock and
  install it without requiring compiler tools on the host.
- Verify a database backup before stopping live processes. Preserve a durable
  cutover journal, restore the previous runtime on startup failure and hold the
  failed candidate. Rollback never rewinds the database or discards accepted writes.
- Retain three updater-created verified backups and preserve active, previous,
  pending and journal-referenced runtimes. Preserve operator files and the
  bootstrap installation. Bound command output and keep owner credentials out
  of package installation and service-child environments.
- Extend native Mac and Linux CI with real signed installation, process restart,
  failed-start rollback and accepted-memory preservation checks. Publish a
  service manifest only after the product and native release gates succeed.
- Return `422 invalid_cursor` for malformed pagination field types across
  memories, evaluations and librarian history, without echoing rejected values
  or opening a pagination transaction (issue 19).
- Let atomic librarian decisions own the retry receipt for their nested memory
  revision. Accept/undo keys can no longer collide with an internal revision key;
  replay preserves exactly one revision per action (issue 20).

## Adoption and compatibility

No database migration, embedding replacement or reindex is required. Existing
services need one host-authorized [managed setup](../service/managed-updates.md)
before they can receive server patches automatically. Existing desktop packages
continue to receive their supported automatic updates independently.

The managed updater covers Linux/macOS Python deployments, including Intel Macs
with Python 3.12/3.13. Windows and Compose servers, database/Python upgrades,
source runners, tunnels, fleet rollouts and schema-changing unattended updates
retain their separate deployment procedures. Cutover briefly interrupts the
service; it does not provide high availability. Keep the original bootstrap
Python installation/checkout and independent disaster-recovery backups.

## Validation and release status

The focused local updater suite passed **87 tests**, including real PostgreSQL,
restricted logins, isolated signed package installation, updater handoff, failed
worker rollback and memories written during the failed candidate's lifetime.
Fixture packages use a temporary test publisher key; these checks do not claim a
public-feed service upgrade or physical reboot. The final local service suite
passed **336 tests**, with two opt-in model skips and **86.05% coverage**. Legacy
checks passed **311 tests** (one skip; 106 excluded by the existing marker policy).
Their independent legacy coverage gate measured **49.07%** against a 45% minimum;
the service retains its separate 75% gate.
The TypeScript client passed seven checks and desktop lifecycle/update policy
passed 24. Lint, formatting, lock and release metadata checks passed.

Chromium verified memory creation, 12 connected workspace screens, all six insight
tabs, evaluation editing and bundled guides. Seven screens fit a 360-pixel window
without horizontal overflow. No external font requests or unexpected JavaScript
errors occurred. A separate missing-bundle fault test verified retained navigation,
explicit reload, cleared credentials, reconnection and keyboard content focus.
These UI checks use isolated fixture data, not model-performance benchmarks.

This file accompanies the release candidate. Full product, browser and all six
native gates remain mandatory before publication; results and public upgrades
are recorded in the [validation report](../validation/2026-10-11-hotfixes.md).
The [product page](https://www.perseusxr.com/mnemion) offers only published builds.

SignPath approval, hosted-agent OAuth, native remote-access setup, further memory
reduction, retrieval evaluations and broader managed deployment coverage remain
on the [roadmap](../ROADMAP.md). OS first-install publisher limitations are unchanged.
