# Mnemion 4.9.0

People can join a workspace using their existing company account. A host
operator connects an OpenID Connect provider; administrators assign people and
spaces, then send a first-login invitation or explicitly link a known company
identity. **Company sign-in** in Studio previews invitation access and opens
the provider's sign-in page. Email addresses and company domains never create
accounts or confer permissions automatically.

The desktop app uses the system browser and a temporary loopback callback.
Company credentials stay with the provider; Mnemion session credentials use the
existing protected desktop store or browser cookie. Each device has a revocable
session, with an eight-hour company lifetime by default. **Account & sessions →
Company access** lists linked identities and lets people or administrators revoke
their permitted links. Revocation immediately ends associated sessions.

The HTTP operation catalog, private CLI and Python/TypeScript clients expose
company configuration and administration. One-use authentication steps require
private files and are excluded from generic MCP execution. See the
[company sign-in guide](../service/company-sign-in.md) for setup, supported
protocols, session policy and agent handling.

Existing personal passwords, remembered sessions and independent agent/recovery
keys remain available. Migration `018_company_sign_in.sql` retains earlier
personal sessions and gives company sessions their own identity links.
Separately hosted servers require the [guarded operator upgrade](../service/managed-upgrades.md).
Desktop updates and local migrations use the normal native release gates.

This advances company onboarding and administrator control. Provider-wide
automatic provisioning, mandatory SSO policy, group mapping, back-channel logout
and company-account consent for hosted assistants remain open. An upstream
account change does not instantly revoke an existing Mnemion session; revoke
its local link or disable the person for immediate enforcement.

[Validation](../validation/2026-10-15-company-sign-in.md) distinguishes service,
upgrade, native-controller and actual Dex/browser evidence. [Release status](../RELEASE_STATUS.md)
tracks installer publication, the live website and public automatic updates.
The full-scope [requirements checklist](../PRODUCT_REQUIREMENTS.md) remains
**17 of 64 shipped (26.6%)**; this milestone advances several partial requirements.
