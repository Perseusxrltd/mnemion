# Mnemion 4.46.11

This candidate combines the [managed backup scheduling repair](../validation/2026-10-25-host-backup-capture.md)
with the native build and validation corrections from the unpublished
4.46.7–4.46.10 candidates. Backup captures wait for active source scans, refresh
their configuration after acquiring the lock and refuse a changed runtime
before writing.

Native setup now reports a bounded database failure category. The installed
model check preserves its first failure and avoids later fixture changes that
could obscure it. [Focused Windows x64 validation](../validation/2026-10-26-native-model-diagnostics.md)
passed setup, memory/recovery journeys and installation/update checks. The
original intermittent restart failure remains preserved without an assigned
root cause. The recovery tests now use an isolated database instead of assuming
that their new job must be first in a shared scheduler queue.

The renderer can reuse only a refused telemetry observation for at most one
second, reducing repeated bridge calls and timer work. Every positive permission
is read afresh, and app privacy changes clear the hints immediately. Focused
checks passed; [compiled app measurements](../validation/2026-10-26-telemetry-renderer-refusals.md)
remain separate acceptance. The collector and other telemetry source work from
the earlier candidates are retained. **Product collection remains unavailable,
with no destination or route enabled; V08 is unfinished.**

[Deployment issue #45](../validation/2026-10-26-issue45-acceptance.md) is closed
against its verified upgrade, backup, restore and documentation criteria. The
PC note publisher retains its separate deliberate pause, and the Grok Bot
cloud-client acceptance remains open.

This candidate still requires its normal release and installed-update gates.
