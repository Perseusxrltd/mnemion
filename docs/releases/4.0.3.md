# Mnemion 4.0.3

This product v1 patch adds native **Windows ARM64** installation and automatic
updates, and reduces local-model RAM without changing existing embeddings.
The complete release targets are Windows, macOS and Linux on x64 and ARM64.
[The product page](https://www.perseusxr.com/mnemion) selects verified published
downloads, versions, notes and guides automatically.

## Changes

- Windows ARM64 installation/update checks now use native system PowerShell.
  The ordinary installer process checks and graceful-shutdown safeguards remain
  active. Native NSIS first installation, signed upgrade, binary verification
  and automatic relaunch passed on Windows ARM64.
- **Issue 13, first mitigation:** share the local model's tokenizer vocabulary
  between complete source counting/chunking and inference. A lock preserves
  inference padding/truncation, including concurrent calls and errors. The real
  pinned E5 and BGE tests verify source-tokenizer semantics and Unicode offsets.
  In the recorded two-thread E5 comparison, loaded process RSS fell from
  **788.4 to 492.4 MiB**; after one 35-chunk document it fell from **1342.9 to
  1059.1 MiB**. Every vector and source span had the same checksum. These are
  controlled single-process measurements, not capacity or quality guarantees.
- Add a reproducible, offline-by-default local-model resource probe. It records
  model/runtime identity, input/output checksums, RSS and timings without user
  memories, database access or model-provider calls.
- Public update rehearsals install a previous unmodified release and observe
  the official feed, real idle guards, replacement process and preserved
  profile. AppImage observation follows the default profile lock; POSIX launcher
  processes are reaped before checking whether the old application has exited.
  Windows x64 and both Mac architectures have passed the public 4.0.1 → 4.0.2
  upgrade with preserved profiles and the original production signing keys.
- Documentation-only and public-probe-only pushes no longer rebuild six native
  installers. Pull-request checks remain unfiltered and releases still require
  the complete selected native matrix.

## Upgrade and compatibility

There is no database migration, embedding-generation change or Obsidian format
change. Keep existing indexes, sources, keys, permissions and notes. Update the
separately deployed **memory server** to receive the RAM improvement; desktop
updates replace Studio and its bundled guides, not the server/database.

API and worker still keep separate model instances, and ONNX allocation pools
can retain memory after large documents. Shared model serving, idle unloading
and further low-memory profiles remain work for issue 13. The embedding batch
size stays unchanged: smaller batches changed quantized output vectors in the
investigation, so they are not silently applied to existing generations.

Windows installers may show an unknown-publisher prompt while free SignPath
approval is pending. Updates verify independent Ed25519 manifests. Mac builds
require macOS 13+, have ad-hoc signatures and signed Sparkle updates, and may
need first-launch Privacy & Security approval. Linux AppImages need a writable
installation; DEBs use administrator/package-manager updates. Organization
security policy remains authoritative. See [updates](../service/updates.md).

## Evidence and next work

The focused memory group passed **19 tests**, including real E5/BGE inference,
source semantics, PostgreSQL retrieval, long documents and concurrency. Release
publication additionally requires the service/Python matrix, SDKs, legacy
regressions, frontend, dependency review and all six native targets to pass on
the release commit. See [the validation report](../validation/2026-10-11.md) and
[the resource results](../validation/2026-10-11-model-memory.json).

Remaining priorities include verified server auto-updates/non-systemd supervision,
hosted-agent OAuth, full discoverable agent administration, source sync triggers,
author-deletion policy and natural-language retrieval evaluations. The issue
queue and [roadmap](../ROADMAP.md) retain those commitments explicitly.
