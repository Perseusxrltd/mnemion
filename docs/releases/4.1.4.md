# Mnemion 4.1.4

Choosing a different **Memory space** in the sidebar no longer blocks a desktop
update as though an editor contained unsaved work. The selector stays mounted
when changing views, so its previous edit classification could prevent every
subsequent safe restart in that app session.

The change identifies this specific navigation control as safe for updates.
Unsaved memory editors, workspace transfers, active use, the normal inactivity
delay and administrator update policy retain their existing protection.

Installed-app checks now exercise the actual space selector, an unsaved memory
and closing that disposable editor through the packaged interface. See the
[reproduction and validation](../validation/2026-10-12-navigation-update-safety.md).

No database migration, model download or credential change is required. If an
older session has already recorded the false blocker, save and close any real
editors, then use the normal **Quit Mnemion Studio** action and reopen the app.
Its ordinary startup check can obtain the latest compatible update. Keep the
[managed source connector setup](../service/managed-connectors.md) from 4.1.3
for separately launched source runners; desktop and server updates have distinct
ownership.
