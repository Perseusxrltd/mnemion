# Mnemion 4.1.2

People and agents can choose keyword-only results when the embedding model's
bounded inference queue is busy. Search and context requests accept
`on_inference_busy: "lexical"`; the default `"error"` preserves the existing
retryable overload response. The option works with hybrid and semantic requests
and returns the explicit `inference_busy_lexical_only` warning. Exact-text context
requests can also use it when token counting is busy. Permissions,
current source visibility, filters and context budgets are still enforced.

Studio adds **If the model is busy → Use exact text** to search and context
controls and explains when the result used that fallback. Older workspace
servers keep the original request shape and show an update hint. Python,
TypeScript, MCP search/context and the agent operation catalog expose the same
choice. Runtime diagnostics count the fallback without recording query text.

When a request searches several embedding generations, one busy generation
switches the complete result to keyword-only retrieval. It stops requesting
model capacity for that call and does not mix an unlabeled partial semantic
result into the fallback. Keyword search can miss matches based on meaning;
retry the original search when semantic coverage is required.

Fallback context packs count **UTF-8 bytes**, shown explicitly in the response
and app, so counting does not wait for the same busy model. If token counting
becomes busy after search, the service rebuilds the whole context with fresh
keyword evidence and a single byte budget. It does not return a partially
assembled context with mixed counting units.

No database migration or additional provider call is required. This release
also includes bounded retries for transient native build source-download
failures. The [source and browser checks](../validation/2026-10-12-busy-fallback.md)
passed. Native publication gates remain pending; current public downloads remain
4.1.1 until the release artifacts are verified.
