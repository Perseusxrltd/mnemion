# Mnemion 4.46.0

Company host controls give approved people and agents a separate way to inspect
and recover a memory host when its memory API or original agent is unavailable.
The app's **Host controls** page opens before workspace sign-in. Each device has
its own OS-protected key and an explicit observer, operator or custodian role.

- Owners adopt an existing managed Unix host and share a pinned public connection.
  The independent controller accepts typed operations over restricted SSH; it
  does not offer an operating-system shell, file transfer or forwarding.
- Operators can inspect the host, start or stop its memory service, review a
  signed update and apply that exact plan. Updating requires a fresh encrypted
  backup and access ledger verified from the configured independent Git
  destination. Existing migration and forward-recovery rules remain enforced.
- An approved stop saves durable service intent. Adoption preserves an already
  stopped service; a new approved start, reviewed upgrade or inspected resolution
  sets the appropriate intent. The OS owner must replace unconditional memory
  startup and watchdog commands with the policy-aware manager and guarded repair
  path described in the [guide](../guides/company-host-control.md#preserve-approved-stops-in-os-supervision).
- Durable operation identifiers survive lost replies and app restarts. An
  uncertain operation remains available for inspection without automatic replay.
  Removing a revoked or unreachable local login can preserve its public recovery
  request first. Private keys never enter these documents or the renderer.
- Custodians grant and revoke host authority. A local OS owner can recover a
  permanent custodian with a reviewed request if all operator devices are lost.
  This authority is separate from memory accounts and vault permissions.
- The native agent controls expose the same enrollment, status, operation,
  access and recovery paths as the desktop app. The controller keeps compatible
  current and fallback runtimes outside ordinary update cleanup.

This is a source candidate. The [source validation](../validation/2026-10-22-independent-host-control.md)
retains 75 integration and 20 desktop checks and a passing Linux source Electron
preview using the real UI, native agent pipe and libsecret. The preview reopened
the same key after a full app restart, authenticated pinned SSH, inspected the
original queued request without replay, enforced the custodian boundary and
archived the public request before removing the local key. Its isolated peer
had no worker, so the approved stop never executed. No product memory service
started; production writes and paid calls were zero. The final preview also
verified the queued UUID and retained recovery request were visible after the
UI settled, and both complete app process phases exited successfully.

The subsequent [durable service-policy revision](../validation/2026-10-22-independent-host-control.md#durable-service-policy--23-october-2026)
passed its source checks and frontend build. The validation retains an
87-pass/two-fixture-error full attempt followed by two targeted SSH passes.
Actual OS job/watchdog integration remains unqualified.

**All six installed-platform gates remain unrun for 4.46.0**, and no production
host was adopted. Source evidence does not qualify installed credential stores,
public availability or production recovery. See the
[host-control guide](../guides/company-host-control.md) for setup and limits.
Initial host adoption supports managed Unix services;
this does not add Windows or container host adoption, a browser control service,
provider power controls, automatic boot registration or full replacement-host
recovery.

The update adds no memory-database migration. Its unreleased host authority
store uses format 2; experimental format-1 state is refused, not silently
migrated or reset. The free product, existing
Obsidian workflow, capture controls and independently managed publisher pauses
retain their established behavior. The full
[continuity contract](../implementation/workspace-continuity.md) and
[roadmap](../ROADMAP.md) remain open where acceptance is incomplete. Published
availability comes from [release status](../RELEASE_STATUS.md).
