# Mnemion 4.46.1

Service startup now loads the setup code for the selected command. API and
worker launches avoid initializing unrelated desktop, recovery and host-client
commands. This reduces CPU contention during managed updates on small shared
hosts while preserving every existing command and its options.

On the canonical one-CPU host, an isolated comparison reduced worker setup
**before database access** from **9.91 to 1.92 seconds**, and CPU time from
**4.90 to 0.95 seconds**. These are single samples of command initialization,
not full service readiness, throughput or retrieval benchmarks. See the
[measurement and regression checks](../validation/2026-10-23-managed-startup.md).

Managed update failures also retain bounded readiness evidence in their
recovery journal and failed-attempt record. `updates status` reports the
last failed version, transition reason, readiness flags and known child states.
An operator can distinguish running processes from a verified, ready service
without disclosing process arguments, connection strings or private logs.
Older failures have no retroactive transition evidence.

Repository registration also keeps its newly opened form when initial host
status arrives. The identity-bound draft reset now completes before the host's
controls become interactive. The
[23 October Windows journal-form validation](../validation/2026-10-23-windows-journal-form.md)
preserves the first frozen Windows x64 failure and the actual Chromium
before/after reproduction with synthetic data. Native diagnostics now identify
the journal field and route through fixed allowlists. Same-host refresh retains
the draft and approval; changing host identity clears them. Frontend/Electron
builds passed. Subsequent
[installed qualification](../validation/2026-10-23-4461-native-acceptance.md)
passed on all six targets, including journal registration and separate approval.
The original failing attempt and earlier source checkpoint remain preserved.

The existing startup/stop deadlines, signed-runtime checks, schema and model
compatibility, verified backup, process identity and rollback rules remain in
force. Failed versions remain held for inspection; this release does not replay
an uncertain operation or unpause a publisher. There is no database migration.

The actual Windows x64 app and shared Linux host passed
[live acceptance on 23 October at 09:55:28 UTC](../validation/2026-10-23-4461-live-acceptance.md).
The host completed its compatible normal update with full readiness; Windows
retained its earlier guarded update without another installation or restart.
Checks confirmed that identities, exact sampled memories, login and preferences
were preserved. The existing 54-request synthetic lab passed with complete
cleanup and no production memory writes or cloud model calls.

The [interruption history](../validation/2026-10-23-4461-live-interruption.md)
preserves the interrupted backup and stopped access comparison, including the
independently verified restoration of previously accepted source roles. The
preceding [4.46.0 rollback](../validation/2026-10-23-4460-live-rollout.md) remains
recorded. Publication and platform gates appear in
[release status](../RELEASE_STATUS.md). Fresh independently verified off-host
backup, OS/controller adoption and two-custodian operations remain pending;
unattended desktop idle restart is not established by this acceptance.

Mnemion remains free. The [full roadmap](../ROADMAP.md) and
[all recorded requirements](../PRODUCT_REQUIREMENTS.md) retain their scope and
completion states. [V08 product telemetry](../implementation/anonymous-product-telemetry.md)
remains Planned and is not part of 4.46.1.
