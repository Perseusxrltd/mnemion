# Mnemion 4.16.0

Git journals now have optional scheduled filing: current memories become readable
Markdown notes for Obsidian, and older day files move intact into `_archive` once
the notes are ready. This completes the filing portion of issue 39.
Grok Build's native ACP transcripts also gain readable conversation companions,
addressing the format gap reported in issue 40.

- Filing reconciles the complete journal, including later revisions, deletions
  and quarantines. Original bytes and stable source identities are retained.
  Generated notes never become independent memories during connector replay.
- Studio adds enablement, age/schedule controls, manual filing and visible
  commit/error, remaining-work and data-volume counters. HTTP, Python, TypeScript,
  CLI and MCP expose the same versioned controls through `journal.organize`.
- Bounded batches use the existing publisher and private SQLite projection.
  Concurrent writers trigger fresh projection before retrying; pending local
  publication, pauses and revoked access block filing. No language-model call,
  GPU or paid service is required.
- Newly published changes clear existing generated views until refreshed;
  withdrawals leave content-free views. Unrelated files remain untouched.
  Historical Git commits still retain their content.
- Migration 023 preserves every existing publisher field and defaults filing
  off. Older clients can update publication settings without resetting filing.
  The app hides filing controls on servers older than 4.16.0.
- Grok Build/ACP capture preserves session identity, streamed text, time bounds
  and raw provenance. Tool/thought/status events remain outside readable turns;
  explicit event IDs support duplicate detection without dropping repeated words.
  Valid Unicode separators inside JSONL messages remain intact on all platforms.

App-only host enrollment, automatic file sharding, old-memory backfill, direct
writable-space reconstruction and live-provider/capacity acceptance remain on
the roadmap. Issue 41 separately tracks bounded capture of growing/partial
transcripts. Existing file and journal inventory safeguards remain in force.
This release does not close issue 39 or replace complete backups.
