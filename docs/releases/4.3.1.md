# Mnemion 4.3.1

Default recall now balances relevance with source age and lowers the priority
of archived task reports. This addresses the reopened
[current-state ranking report](https://github.com/Perseusxrltd/mnemion/issues/31),
where archived filenames outranked newer answers. The original relevance score
and minimum-score filter remain comparable; each result also explains its
ordering score and age/archive factors.

The app, API, SDKs and full MCP search/context tools expose the same
[ranking preferences](../service/retrieval.md#current-state-ranking-preferences).
People and agents can tune recency, the age half-life, archived weight and
literal archive directory names, or restore pure relevance. `done` directories
keep their ordinary priority. Windows/Unix separators and Unicode are supported.
The app shows the date used for ranking and only sends new preferences to a
compatible server. Python clients omit the new field unless explicitly requested.

Current access, source leases, quarantine and historical-revision checks still
apply before ranking. Preferences do not exclude evidence, change claims, expand
candidate windows or load another model. There is no database migration from
4.3.0 and no re-index requirement. Older managed hosts still need any migrations
they have not yet applied through the [guarded upgrade](../service/managed-upgrades.md).

[Focused validation](../validation/2026-10-14-current-state-ranking.md) covers
real PostgreSQL order changes, archive opt-out, historical dates, unchanged
thresholds, existing access/race checks, bounded inputs, MCP and older-server
compatibility. Source dates remain hints; automatic contradiction resolution,
dated-section chunking and broad quality calibration remain roadmap work.
Publication, native builds and public upgrades are tracked in
[release status](../RELEASE_STATUS.md).
