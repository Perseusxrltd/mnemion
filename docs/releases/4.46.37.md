# Mnemion 4.46.37

Desktop service requests now reject promptly when the SDK deadline or the
caller's cancellation signal fires, instead of waiting for the native reply.
Native network and response-body work receives the cancellation signal;
renderer teardown and accepted application shutdown also cancel owned requests.
Cancellation cannot undo work the server has already performed. Session
rotation and retry/idempotency behavior remain unchanged.

This release also carries the already-main
[Python telemetry action-timing correction](../validation/2026-10-27-telemetry-agent-timing.md):
recorded latency includes the optional local policy reads before an action.
This improves measurement accuracy without establishing a resource saving.

The [cancellation report](../validation/2026-10-27-desktop-request-cancellation.md)
retains both original regression failures. All 32 focused checks and the
SDK/frontend/Electron builds passed. A real Linux x64 Electron source-app check
confirmed cancellation before response headers and during response streaming,
with cancellation tokens kept out of server traffic. The same three checks are
now required by the six-platform installed release gate; those installed results
and release qualification remain pending. The
[release-status document](../RELEASE_STATUS.md) owns public availability.
V08 remains Building with production collection disabled; full telemetry
and resource acceptance remain open, with resource limits unchanged.
