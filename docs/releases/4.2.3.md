# Mnemion 4.2.3

This release combines agent compatibility and search controls. MCP clients can
use the short `search` and `fetch` aliases. Operators can select compact discovery
with four tools and paginated access to the full administration catalog, or
enable native MCP sessions for clients that require a session ID. Sessions remain
bound to the credential that created them, and every request rechecks access.
See [agent setup](../service/agents.md#compact-discovery-and-session-compatibility).

Search and context requests accept newest-first ordering, a recorded-since
filter, minimum rank score and a minimum similarity for meaning-only matches.
The app exposes these under **Search order and match filters** when connected to
a compatible server. Responses identify empty, semantic-only and literal-match
results. These are observable match types, not calibrated answer confidence.
Default ranking remains compatible; thresholds are chosen for the workspace's
model and evaluations. See [retrieval controls](../service/retrieval.md#order-and-match-controls).

Git imports preserve the last commit time for each file. The first scan with this
connector refreshes existing Git records once to add that date, with ordinary
indexing work; later unrelated commits leave unchanged files alone. Existing
records keep their stable memory identities and access boundaries.

Release preparation retains the complete product, installation, signature and
update gates. Main pushes no longer also start a duplicate six-platform desktop
build. Pull requests and manual native checks remain available. Public downloads,
website version information and update feeds continue through existing automation.
Version preparation, source freezing and release dispatch now have one repeatable
CLI. Successful automatic artifact verification triggers guarded publication,
website synchronization, complete public-upgrade checks and retained per-version
evidence. Existing matching runs are reused; failures remain visible instead of
starting repeated builds. See [release automation](../implementation/release-automation.md).

No database migration is added after 4.2.0. Hosts still on 4.1.x need the guarded
[schema upgrade](../service/managed-upgrades.md) before automatic compatible patches. The optional compact and
session modes require a gateway restart; the default full, stateless interface
remains available. Sessions are process-local and expire after 15 idle minutes;
multiple workers require routing a session to its original worker.

[Focused validation](../validation/2026-10-13-search-agent-batch.md) records the
checked behaviors and limits. [Live release status](../RELEASE_STATUS.md) records
publication and platform gates. General natural-language quality, dated-section
chunking, hosted identity onboarding and the remaining product requirements
continue on the [roadmap](../PRODUCT_REQUIREMENTS.md).
