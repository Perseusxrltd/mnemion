# Mnemion 4.46.55

This note proposes the integrated product-telemetry update. It does not turn
collection on, and it does not authorize a production destination. The saved
preference still defaults to enabled. Collection stays unavailable, with no
destination and no release route. Progress in source is not live fleet
collection. V08 remains Building.

The pending report is one 25-byte bounded summary. It carries 19 metrics for
usage, reliability, performance and resources. Each report compares either
release versions or a coarse operating system — Windows, macOS, Linux or
other — and not both as one joined profile. A category disabled by company
policy, and a sensor that did not report, stay visible as their own results
rather than as a zero. Memories, prompts, token text, keys and identifiers are
excluded. The summary is not a count of people or an exact uncapped event
total. The collector can read one summary. Noise is added to the published
week, which is not network anonymity or collector blindness.

Saved opt-outs, company restrictions and manual review remain in force. An
approval stored for the older four-byte report is invalidated and is not sent.
Sending is refused when any group covered by the prepared summary is no longer
permitted. Ordinary Privacy settings do not show fleet data. The choice and
review controls are described in
[privacy controls](../guides/product-telemetry-controls.md).

Maintainers can export a private self-contained HTML, CSV or JSON report from
a sealed store. That export is not the in-app Privacy page. Preparing a
release keeps the release comparison list current: it adds the current version
and the version being prepared, keeps at most 32 entries, and leaves any other
version unlisted. A week already closed keeps the list it was published with.
The [v3 reference record](../validation/2026-10-29-telemetry-v3-reference.md)
holds those checks.

Client encoding is recorded in the
[shared encoder note](../validation/2026-10-29-telemetry-v3-client-encoder.md).
Wiring that encoder through the app is still finishing in a separate checkout.
A native check that used a temporary fallback is not acceptance; that fallback
is being removed, and the shared-review checks are to run with the compiled
helper. The final release matrix has not run. The
[qualification probes](../validation/2026-10-29-telemetry-v3-probes.md) and
[phase-memory diagnostic](../validation/2026-10-29-telemetry-phase-memory.md)
do not pass installed v3 delivery, the resource gates, or provider
qualification.

This batch follows the [4.46.54 corrections](4.46.54.md). All 66 requirement
states remain unchanged. The normal release and website automation records
published installers, update availability and download details in
[release status](../RELEASE_STATUS.md).
