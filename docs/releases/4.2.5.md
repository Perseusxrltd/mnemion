# Mnemion 4.2.5

Managed Linux/macOS services now share one worker-owned local embedding cache
between indexing, API search, context token counting and evaluations. This
removes the API's second model copy by default, including after an older managed
bootstrap installs the current runtime. Native local workspaces already share
their registry; independently deployed containers keep their existing lifecycle.

The [offline E5 comparison](../validation/2026-10-14-shared-model-runtime.md)
measured **37% less combined resident RAM** across the two model processes.
Query vectors, document vectors and Unicode spans were identical. Database,
desktop and other host memory are excluded; this is not a universal minimum
specification. Model fingerprints and stored indexes are unchanged.

The worker uses one inference gate for local search and indexing. Idle cleanup,
bounded admission and optional keyword fallback remain available. A private
loopback connection authenticates both ends with a per-worker credential and
pinned TLS certificate. Worker restart rotates the credential and certificate;
API requests reconnect without loading a fallback model. Operators retain a
`MNEMION_MODEL_SHARING=0` compatibility setting.

**Insights & evaluations → Models & resources** shows the model owner and
separate worker RSS, queue and cleanup gauges. Busy or restarting workers remain
explicitly unavailable. Observation does not load models or prolong their idle
lifetimes. The Python API contract and TypeScript client include the optional
worker snapshot for authorized administrators and agents.

Repository automation now attaches fixing-version labels and closes reviewed
issue resolutions after their exact release passes and becomes public. A report
that users reopen remains open. No issue comments or additional services are
required. Release monitoring, version preparation, integration, publishing,
website synchronization and evidence retention continue through the existing
scripts and GitHub workflows.

The [full product requirements](../PRODUCT_REQUIREMENTS.md) remain intact.
Fleet resource policy, representative throughput measurements and deployment
types outside managed Supervisor remain separate work. Public package and
upgrade results are recorded in [release status](../RELEASE_STATUS.md).
