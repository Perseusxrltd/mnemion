# Mnemion 4.27.0

This release makes database recovery portable across operating-system locales.
A real independent-computer restore exposed the problem: a PostgreSQL 17 backup
from a `C.UTF-8` host contained intact memories, but PostgreSQL 18 rebuilt its
generated keyword index differently on a destination using `C`. Earlier releases
correctly refused publication because the full row hashes differed.

New backups record their source locale and use table-inventory version 2. Every
memory field, revision, identity, source, embedding and other stored table value
is verified. Only `memory_revisions.search_text` is regenerated by PostgreSQL;
its exact packaged generated-column definition is checked before exclusion.
Counts and hashes still have to match before the destination is published.

Existing backups retain their original full-row verification. Operators can use
`--database-locale` with `mnemion-service restore` or `mnemion-service host restore`
to select a compatible installed libc locale. Host restore records that choice
and refuses a retry that changes the reviewed destination settings. New portable
backups require 4.27 or later for general cross-locale recovery.

The installed desktop recovery probe also waits for controls to remain mounted
through rendered frames before interacting with them, and identifies the
selector if a field is unavailable. Its actual encrypted backup, independent
database restore, deletion, vault, restart and access checks are unchanged.

The release carries 4.25's legacy buffer importer and 4.26's editable native
journal recovery. See [journal recovery](../service/journal-recovery.md) and
[host recovery](../service/host-recovery.md). Publication and six-platform update
acceptance remain release gates; a source version is not a download claim.

Validation and the independent-host drill are recorded in
[the recovery report](../validation/2026-10-19-portable-host-recovery.md).
Roadmap coverage remains **17/64 (26.6%)**; issue fixes do not complete unrelated
roadmap requirements.
