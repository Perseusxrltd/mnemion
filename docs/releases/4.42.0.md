# Mnemion 4.42.0

Reconnect existing folder and conversation sources through Studio while retaining
their original memory identities and authorized readers.

- **Folder continuity:** a source first enrolled through a CLI adapter keeps its
  recorded filesystem namespace. The former desktop default could create a second
  source, suspend the original and report success while its readers lost access.
- **Conversation continuity:** the app and native agents can supply the original
  conversation identity. Enrollment checks the recorded file catalog before
  importing; an unknown identity, unrelated replacement or missing original file
  stops without changing the original memories.
- **Verified copied captures:** new checkpoints record a captured-prefix hash.
  A copied folder can retain the same memories and versions after those bytes
  are verified, even when its filesystem identity changes on another device.
  Normal append, rotation, truncation and file removal continue to work.
- **Private, persistent controls:** the verified selection survives restarts and
  its identity cannot silently change. App setup explains retaining relative
  file paths and stopping the previous runner before starting its replacement.

An older conversation checkpoint without portable verification needs a scan on
its original file with this version before making the replacement copy. Retain
existing memories if that original is unavailable; an unverified copy is refused.
These controls preserve ordinary source access mapping and complete-inventory
removal rules. No paid service or model is required.
