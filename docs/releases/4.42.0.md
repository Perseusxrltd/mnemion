# Mnemion 4.42.0

Reconnect an existing folder source through Studio while retaining its original
memory space and authorized readers.

- **Preserved source identity:** a folder first enrolled through a CLI adapter
  keeps its recorded filesystem namespace when connected through Studio. The
  earlier desktop default could create a second source, suspend the original
  as `access_lost` and report a successful scan while its readers lost access.
- **Checked before import:** enrollment and each scan verify the connector's
  recorded folder identity. Ambiguous or malformed catalogs and an explicitly
  mismatching identity stop before importing. New sources keep the existing
  default namespace.
- **Matching app and agent controls:** the verified `scope_id` survives private
  settings and agent status. An existing identity cannot silently change.
  Setup explains choosing the genuine folder or its restored copy and stopping
  the previous runner before starting its replacement.

This reconnects available folder data; it does not recover an offline computer's
files, take over arbitrary runners or validate unavailable cloud providers.
[Issue 46](https://github.com/Perseusxrltd/mnemion/issues/46) remains open for actual
source revalidation. Existing access mapping and complete-inventory removal rules
still apply; no new paid service or model is required.

See [folder reconnection](../service/desktop-sources.md#reconnect-an-existing-folder)
and [source validation](../validation/2026-10-20-source-identity-recovery.md).
Native delivery, publication and live acceptance remain separate release gates.
