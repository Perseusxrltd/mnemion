# Mnemion 4.0.4

This patch adds discoverable agent administration across the existing API and
keeps Linux login startup working when an update renames its AppImage.
Windows, macOS and Linux remain available on x64 and ARM64 through
[the official product page](https://www.perseusxr.com/mnemion).

## Changes

- Add a reviewed catalog of **81 operations**, authenticated server discovery,
  an offline `mnemion-control` CLI and four compact MCP discovery/execution tools.
  Agents can administer teams, connectors, models, librarian jobs, evaluations
  and monitoring with their existing permissions. Schemas load on demand.
- Validate operation requests, distinguish reads/writes, preserve idempotency
  keys and respect `Retry-After`. An interrupted administrative write without
  idempotency is reported as an unknown outcome and is not replayed.
- Bound input, response size, retries and transfer budgets. Large exports go to
  private files; newly issued API keys never enter generic MCP transcripts or
  ordinary CLI output. New key files work directly with the existing agent
  setup commands. Windows uses a protected owner-only file ACL.
- Regenerate the operation contract in CI and reject unclassified API routes or
  drift. Existing SDK methods and primary memory MCP tools remain supported.
- Follow the Linux AppImage's updated filename in its existing login entry,
  including migration on the first launch of this patch. Preserve OS disable
  flags, deleted entries and custom startup commands. Public Linux rehearsals
  now check that the login entry points to the actual installed update.

## Upgrade

No database migration, embedding-generation change or Obsidian format change is
required. Upgrade the **server/gateway and Python environment** for the new agent
operations; desktop automatic updates supply Studio, bundled guides and the
Linux startup correction. Refresh the assistant's tool connection after its
gateway restarts. See [agent administration](../service/agent-control.md).

The preceding 4.0.3 release introduced Windows ARM64 and reduced local embedding
RAM. Public 4.0.1 → 4.0.2 upgrades passed on Windows x64, both Macs and both Linux
architectures using the official feeds and unmodified apps. The website picked
up 4.0.3 and all six downloads automatically. See
[the dated evidence](../validation/2026-10-11.md).

## Validation and limits

Local service regression checks passed **237 tests**, with two opt-in model
checks skipped and **85.77% service coverage**, before the final probe additions.
The final focused agent/probe/private-output group passed 18 tests, with one
Windows-specific skip on Linux, including live HTTP/MCP,
permission isolation, revoked keys, uncertain writes, response limits and slow
transfers. Native Windows x64 separately passed private-file creation, reopen,
exclusive-write and protected-DACL checks. The release workflow additionally
requires all selected native and product gates before producing its draft.
Desktop update/startup checks passed all 24 cases. The full local client suite
passed 70 tests with two platform skips before the final permission-enforcement
case; that case passed in the focused group. Studio's production build includes
the operation guide, updated roadmap and these release notes.

OS publisher restrictions remain: Windows may show an unknown-publisher prompt
while SignPath approval is pending; Mac first installation may require Privacy
& Security approval. Both platforms authenticate updates with independent
signatures. Linux AppImages need writable installation directories; DEBs follow
package-manager policy. See [updates](../service/updates.md).

Hosted OAuth, managed server updates/non-systemd supervision, source-sync
triggers, further memory reductions and retrieval evaluations remain on the
[roadmap](../ROADMAP.md). Agent API access retains its current permissions;
host/database administration continues to use operator credentials.
