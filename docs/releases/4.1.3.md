# Mnemion 4.1.3

Source connectors can follow the verified runtime of an adopted Linux/macOS
service host. Start `mnemion-connect --watch --config /private/connector.json
--managed-state /private/managed-service` using a stable bootstrap installation.
The existing source identity, configuration and credential references remain.
Stop the previous runner before switching its startup command.

Each complete scan uses the current verified package. Shared scan leases let
concurrent connectors finish before an update; a waiting updater pauses new
scans and retries shortly. The next scan follows a successful update or restored
rollback. Compatible future runtimes also update the launcher itself between
scans. Duplicate managed launchers are refused, and ordinary shutdown drains
the scan and its provider processes.

Host update status now includes managed connector liveness, launcher version and
latest scan version without exposing provider paths, credentials or content.
Scan reports identify their actual version, and plain `--watch` explicitly
reports manual update ownership. See the
[setup and lifecycle guide](../service/managed-connectors.md) and
[validation record](../validation/2026-10-12-managed-connectors.md).

Authenticated MCP clients also gain a stable, opaque profile identity tied to
the current principal, supporting clients that request `openai/profile` metadata.
The release includes the tested, bounded Argon2id foundation for future individual
sign-in. It does not yet add account/password routes, browser sessions or hosted
OAuth consent; those remain on the [roadmap](../ROADMAP.md).

No database migration, model replacement or paid provider is required. The
release pipeline now verifies uploaded packages on a separate hosted runner,
and public update/website metadata fetches retry bounded transient GitHub gateway
failures. Remotely hosted connectors, unmanaged processes and Windows/Compose
fleets keep their separate deployment ownership.
