# Mnemion 4.1.1

API and indexing-worker processes release local embedding sessions after five
minutes without inference. The next semantic request reloads the same approved
model from disk. Active and queued calculations remain protected; model files,
fingerprints, indexes and memories are preserved. This reduces retained idle
allocations; API and worker still have separate peak working sets.

Administrators can inspect the cleanup interval, loaded-model count, release
count, monitor status and cleanup retries in **Insights & evaluations → Models
& resources**. Agents receive the same observations through the existing
authenticated runtime-insights API. Older servers can omit these optional fields.

Operators can use `MNEMION_MODEL_IDLE_SECONDS=0` to keep models warm, or set
10–86400 seconds. The default is 300 seconds. Cleanup failures are counted and
retried without exposing native-provider error text. Native RAM-budget controls
continue to apply separately. See the [resource guide](../service/memory-resources.md).

This patch uses the existing database schema. Adopted 4.1.0 managed services
can use the signed compatible patch channel; a 4.0.x shared host still needs
the controlled 4.1.0 schema migration first. Desktop and shared-service update
ownership remain separate. Product checks and real-model measurements passed
on Linux and both Mac architectures; native packaging and public publication
remain pending while this source version is validated.

The [validation record](../validation/2026-10-12-model-idle-cleanup.md) records
the completed local service, client and responsive UI checks and remaining gates.
