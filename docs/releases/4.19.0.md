# Mnemion 4.19.0

Desktop connections now retain the authenticated server's version, so supported
features such as Git journal setup appear correctly. Saved connections refresh
this metadata from the server on reconnect. The new installed-app check caught
the missing metadata in 4.18, which was withheld; this release includes its
guided Git setup with the correction.

Busy workspaces can keep publishing a writer's daily Git journal after its first
20 MB file fills. Complete records roll into numbered continuation files; earlier
files remain intact. Retries find previously published events across active and
archived parts, including after losing the local publication cache.

- A private SQLite index stores immutable Git object IDs and event hashes, with
  a 2 MiB page cache. Sealed files are not reread for each append; changed objects
  are validated again. It stores no memory text and rebuilds from Git after loss.
- Filing preserves every part in the archive and applies the complete inventory
  of revisions and deletions before producing readable notes. Missing parts,
  conflicting retries and resource limits refuse publication or filing.
- The first continuation upgrades the catalog to schema 2; record schema 1 and
  original paths remain intact. **Upgrade every publisher and journal-reading
  source runner to 4.19 or later before relying on rollover.** Older versions
  refuse a schema-2 catalog. This avoids silently overlooking a continuation.
- Four new private desktop operations let local agents inspect app update policy,
  change a preference using its observed value, check immediately and request a
  verified update's restart. The catalog now has 30 local operations. Memory
  credentials and remote agents do not gain OS-account authority.
- Restart requests require the exact ready version and explicit confirmation.
  They retain unsaved-work checks, active-operation checks, clean shutdown and
  signature verification. Refused requests do not leave a persistent override
  of the normal background/inactivity policy.

No new model, paid service, dependency or database migration is required. The
20 MB per-file, one-million-record/2 GiB inventory and existing batch limits
remain bounded; rollover is not unlimited history or a fleet throughput claim.
Old-memory backfill, external-buffer reconciliation, provider sign-in, direct
writable reconstruction and independent hosting remain on the roadmap.
