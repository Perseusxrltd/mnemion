# Mnemion 4.46.59

Desktop source capture sleeps until work is due. Empty and fully paused source
lists no longer keep a two-second scheduling timer alive. Enabled sources use
their saved scan deadlines; startup, configuration changes, resume and manual
Sync can wake the scheduler. Due sources retain one active scan and a bounded
gap between automatic scans. Update suspension and app shutdown cancel pending
wakes, including callbacks that arrive late. See
[desktop source behavior](../service/desktop-sources.md).

Resource diagnostics also gain corrected Windows lifetime counters, Mac peak
RSS and descendant observations, and separate app-main and renderer RSS at
installed workload checkpoints. Missing lifetime coverage remains explicit in
the [native counter report](../validation/2026-10-31-native-memory-counters.md)
and [installed process-role report](../validation/2026-10-31-installed-process-roles.md).

Strict TypeScript compilation and all 110 focused source/capture checks passed
before packaging. The
[scheduler validation](../validation/2026-10-31-source-deadline-scheduling.md)
records the original checks and their limits. Fewer scheduled idle wakeups do
not establish measured CPU or RAM savings across the whole application; the
[runtime efficiency work](../implementation/runtime-efficiency.md) continues.

Production product telemetry remains unavailable while collector hosting and
resource acceptance are completed. [Release status](../RELEASE_STATUS.md),
downloads and website notes follow the existing release automation.
