# Mnemion 4.46.44

Source-health warnings now have an explicit diagnostic view for tenant
administrators and connector operators. It identifies affected sources, the
responsible connector identity, fixed failure reasons and the next recovery
step. The API, Python/TypeScript SDKs, MCP and app share this view. Diagnostics
are paginated and retain the existing source-control permissions; ordinary
space access does not grant connector administration.

Connections adds a Source availability panel with links to existing controls.
An intentional pause stays in place until an administrator resumes it, and a
resumed source still needs fresh provider permission checks. Opening diagnostics
never resumes a source, requests a scan or changes an identity.

Canonical telemetry documentation now links to the generated Git inventories
for current coverage and preserves dated qualification counts. It describes the
current catalog/report versions while retaining older report compatibility.
Telemetry remains Building, with production collection disabled and full
resource, wire, provider/privacy and platform acceptance outstanding.

Release preparation now generates telemetry coverage after its API contract,
preventing stale source hashes when an interface changes. All **57 focused
Python cases**, Studio/SDK builds and **22 SDK tests** passed; the
[qualification record](../validation/2026-10-28-source-diagnostics.md) preserves
the original preparation failures and the validated correction.

The [control guide](../service/agent-control.md) documents the recovery sequence.
This continues the [field reliability plan](../implementation/multi-agent-field-readiness.md);
issues 44, 47 and 48 and the original 66 requirement states remain open or
unchanged. Qualification and public availability are recorded in
[release status](../RELEASE_STATUS.md); this source note does not establish an
installed release.
