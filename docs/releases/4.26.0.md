# Mnemion 4.26.0

Restore current journal content into editable native memories through the app,
Python/TypeScript SDKs or private agent controls. Complete catalogs and archives
are checked before any write. Original memory IDs are preserved by default;
explicit independent copies support a separate private destination.

Deletions, missing-text quarantines, older snapshots, conflicting versions and
local edits retain distinct recovery decisions. Newer reviewed source content
can update untouched recovered memories. All writes and indexing jobs commit
together. Source writers do not become users or receive permissions.

The guided recovery accepts a complete journal up to 1 MiB and 1,000 identities.
Never split its catalog to fit. Original accounts, vault contents and full
history require complete workspace backup recovery. Large-inventory upload and
the remaining issue 39 deployment checks remain open.

Newer recovery ledgers preserve later quarantines, even without memory text or
a space in the older backup. They retain manual review decisions without
treating the ledger as a backup of newer content. Ledgers with these holds use
format version 2, which older software refuses; restore them with 4.26 or newer.

This release also carries the reviewed older-buffer importer from withheld
4.25. Its installed check selected a textarea from the previous journal page
while navigation was still completing. The check now waits for the actual
memory editor and continues to verify that unsaved work prevents update restarts.
Recovery forms release their restart guard after saving, clearing or exporting;
selected files, unsaved changes and pending requests remain protected.

Migration 027 adds the private origin registry. No new runtime dependency,
model download or paid service is required. See the
[recovery guide](../service/journal-recovery.md) and
[validation record](../validation/2026-10-19-native-journal-recovery.md).
Publication and installed updates retain their normal automatic gates.
