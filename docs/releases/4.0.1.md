# Mnemion 4.0.1

Release preparation, 2026-10-10. This is a patch of the first shared-memory
platform (product v1). macOS and Linux 4.0.0 remain available from
[the product page](https://www.perseusxr.com/mnemion) while the new artifacts are
validated. Windows downloads become available only after publication.

## Changes

- Add the Windows x64 and ARM64 full NSIS installer delivery path with
  independently signed Ed25519 update manifests. The installed app authenticates
  the exact version, architecture, immutable URL, size and SHA-512 before use.
- Bound update metadata, disk use, transfer time and idle connections. Hash
  installers incrementally and verify existing caches again before execution.
  Modified caches, older versions, wrong architectures and unsafe redirects are
  rejected. Pausing and ordinary quitting cancel pending Windows updates.
- Wait for an idle, unfocused session with no draft or vault/API work, and check
  again before installation. Keep the running app available when launching the
  installer fails. Use a dedicated cookie-free network session with explicit
  GitHub redirect handling and bounded stream queues.
- Disable Electron's Node environment and inspector overrides in distributed
  apps; load code only from the packaged ASAR, with embedded integrity validation
  on supported Mac/Windows platforms.
- Preserve Mac/Linux update feeds and offline documentation. Report the actual
  package version in the MCP handshake instead of the old alpha identifier.
- Pin a compatible Windows archive filter so NSIS extracts ARM64 executable
  files and DLLs instead of silently omitting them. Compare installed binary
  hashes and test paths containing spaces during native release validation.

## Compatibility and installation

No database migration or memory format change is introduced. Existing service,
SDK, MCP and Obsidian workflows keep their contracts. Server deployments remain
administrator-managed; the desktop updater never upgrades a company's database.

Windows requires an x64 or ARM64 Windows 10/11 system compatible with the bundled
Electron runtime. Choose the matching installer on the product page. The free
installer does not yet have a Windows publisher certificate; Windows may show an
unknown-publisher prompt, and company policy may require administrator approval.
SignPath enrollment remains pending. Update signatures do not bypass SmartScreen
or security policy. See [installation and updates](../service/updates.md).

Mac requires macOS 13 or later. Free Mac builds use ad-hoc app signing and
independently signed Sparkle updates; first installation may require Privacy &
Security approval. Linux AppImage supports built-in updates in a writable
location; DEB updates remain managed by the package administrator.

## Validation and release gate

The preceding implementation passed the full Python 3.12/3.13/3.14 service,
legacy, SDK/Studio, lint and dependency checks in
[run 38080508108](https://github.com/Perseusxrltd/mnemion/actions/runs/38080508108).
Current local desktop tests cover metadata/signature/URL tampering, payload and
cache verification, resource limits, cancellation, expiry, guards and recovery.
Native Windows checks rehearse actual NSIS installation, update and relaunch in
disposable copies; the final release commit must pass those checks on both
architectures and retain the existing Mac/Linux checks before publication.

Each release manifest must verify with the public key embedded in the actual
package. Published installers, feeds and checksums are immutable. See the
[Windows implementation](../implementation/free-windows-updates.md),
[signing policy](../CODE_SIGNING.md) and [roadmap](../ROADMAP.md).

Remaining work includes broader operating-system and managed-device coverage,
live provider contracts, larger quality/load evaluations, organization identity
and lifecycle management, connector onboarding and further operational controls.
These are tracked explicitly; this patch does not claim universal deployment
validation or end-to-end encrypted searchable memory.
