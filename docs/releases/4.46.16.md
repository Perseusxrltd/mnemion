# Mnemion 4.46.16

Independent host administration now distinguishes a newly accepted request from
one returned after a retry. Optional telemetry uses that distinction to avoid
counting the same admin action again after a connection drops. Check the automatic
[release status](../RELEASE_STATUS.md) for download availability and platform
qualification.

The desktop app and its native agent interface recognize nine typed host
mutations, including backup verification, upgrade planning and operator changes.
They measure only a verified new intake. Status checks, readbacks, replays,
refusals, lost replies and older hosts without the new field remain unmeasured.
Queued work is recorded as accepted; that does not imply its eventual success.
The existing protocol envelope, durable operations, permissions and retry
identities remain compatible, with no database migration. No host IDs, keys,
paths, request bodies or memory content enter telemetry.

[Focused validation](../validation/2026-10-26-telemetry-host-requests.md) passed
**47 Python and 17 Node checks**, without skips, plus the Electron build and
Python lint checks. These include concurrent intake, real pinned local SSH,
lost-reply recovery, grant/revoke replay, privacy refusals and unchanged action
results. Installed platform acceptance is a separate release gate.

[six-journey storage follow-up](../validation/2026-10-26-telemetry-storage-followup.md)
on earlier source: 2,322 successful fixture API requests, 2,304 memory operations,
no model calls and verified cleanup. Memory overhead still exceeded the unchanged
2 MiB target. All original outcomes remain retained; further performance work
requires an architecture decision.
