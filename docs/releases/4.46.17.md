# Mnemion 4.46.17

This update corrects native telemetry handoff and package validation, while
production telemetry remains disabled. See automatic
[release status](../RELEASE_STATUS.md) for availability and platform qualification.

The native sender now finishes its own in-progress privacy observation before
taking the mandatory fresh handoff check. This prevents an asynchronous Windows
permission read from occupying the single storage slot needed by the same send.
Policy watching resumes after handoff; the five-second socket deadline, opt-out
checks, one-handle limit, spending and final cleanup remain enforced. TLS test
fixtures also stop waiting for a peer when delivery has already finished or a
finite fixture deadline expires.

The builder, sender and packaged-resource verifier now share the active wire
definition. Incremental builds remove retired wire files, and package validation
requires wire v2. This resolves the obsolete wire-v1 requirement recorded in the
failed 4.46.15 packaging jobs.

The update carries forward [host-intake ownership](../validation/2026-10-26-telemetry-host-requests.md)
from the held 4.46.16 candidate. Nine typed desktop/native-agent host mutations
can contribute only after a verified new intake. Replays, readbacks, refusals,
lost replies and older hosts remain unmeasured. Queue acceptance does not imply
terminal success, and no host identities or request contents enter telemetry.
Wire v2's fixed manual body and report v3's automatic-only categorical estimates
remain unchanged.

At the **26 October source checkpoint**, [focused validation](../validation/2026-10-26-telemetry-release-guards.md)
passed **37 Linux checks** and **17 actual Windows x64 transport checks**, without
skips, plus the Electron build. Original failures remain preserved. Six-target
native/public release acceptance is still pending at this checkpoint; public
4.46.13 remains available. The earlier host-intake checks remain separate evidence.

**V08 remains Building**, with collection unavailable and destination/route null.
The private SQLite adapter is still a feasibility prototype, not a replacement
backend or an RSS improvement. All 66 requirement texts and states remain
unchanged; the **2 MiB / 0.5%** resource gates, full platform, wire, privacy and
utility qualification remain open.
