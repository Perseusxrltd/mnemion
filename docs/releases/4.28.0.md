# Mnemion 4.28.0

Trusted agents on the user's computer can now connect Studio to a team workspace,
inspect saved accounts, reconnect, sign out and return to the local workspace
through the app's private control interface. Setup can continue while the app is
in the background or the screen is locked.

Nine new operations use the existing connection manager and OS-protected storage.
Key connections require the intended organization and person as well as the
observed connection revision. Stale requests and changed identities are refused;
unsaved drafts and pending app requests remain protected. Status never returns
the stored key, refresh token or internal native session handle. Personal password
sign-in retains normal refresh and server revocation. Unavailable secure storage
does not fall back to plaintext.

The displayed workspace follows accepted agent changes, and the app's own
connection actions cannot race a private operator mutation. A failed connection
preserves the previous selection. Local hosting and startup preferences remain
independent of the selected remote account.

The [operator guide](../service/desktop-operator.md#select-a-team-workspace-from-a-local-agent)
documents the 39-operation catalog and private stdin workflow. The copied local
agent setup now includes connection discovery. [Validation](../validation/2026-10-20-desktop-workspace-control.md)
records focused checks and the required installed-app acceptance.

The batch also records [real hosted HTTPS OAuth acceptance](../validation/2026-10-20-live-hosted-signin.md)
and explains persistent host setup. That protocol exercise does not establish
signed-in ChatGPT or live managed-ngrok acceptance; issues 3, 4 and 18 remain open.
All existing memory, recovery, Git journal and update capabilities are retained.
Public installers and automatic updates appear only after their release gates.
Strict full-roadmap coverage remains **17/64 (26.6%)**.
