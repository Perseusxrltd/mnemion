# Mnemion 4.46.57

Telemetry admission now works consistently when a browser cannot report CPU
pressure, heap usage or network cost. Automatic mode permits a bounded attempt
on an unknown network; detected metering, data saving, pressure, offline state
and hidden pages still pause delivery. Invalid live readings cannot reuse an
earlier permissive value, and losing a sensor cannot clear a known restriction.

Disclosure version 3 explains this behavior. Previously enabled installations
need a fresh explicit acknowledgement before collection can resume. Editing
connection settings does not acknowledge it. Opt-out, manual review, company
restrictions and spent traffic budgets remain preserved. See the
[source qualification](../validation/2026-10-30-telemetry-browser-admission.md).

The repository also gains an automated installed-app delivery diagnostic for
all six platform targets. It packages a disposable loopback configuration,
exercises real memory actions and review controls, checks the received report,
and verifies restart persistence. These diagnostic packages are not published.
The [driver source checks](../validation/2026-10-30-telemetry-installed-driver.md)
passed; the installed journey remains to be qualified.

Product telemetry remains unavailable: there is no production collection
destination or live fleet report. Installed delivery, actual browser journeys,
resource limits and operated collector qualification remain open under V08.
The diagnostic's existence does not establish acceptance. The
[telemetry guide](../implementation/anonymous-product-telemetry-v3.md) tracks
those limits; [release status](../RELEASE_STATUS.md) updates automatically.
