# Mnemion 4.1.0

Contributors can withdraw their own ordinary, unverified memories when no other
identity has revised them. Agents can correct their own mistakes without being
given reviewer authority over a whole space. Studio shows **Withdraw your memory**
when the current server reports permission; API, SDK and MCP controls use the
same checks and deletion pipeline.

Reviewers retain their existing controls. Other authors' changes, quarantine,
verified claims, expired credentials and revoked access remain protected.
Permission is rechecked after waiting for an edit or deletion lock. An ineligible
visible memory returns `requires_reviewer`; a fetched memory can report
`can_forget` without turning that observation into a lasting grant.

Librarian prose derived from the deleted note is erased in the same transaction,
even when the contributor cannot read that protected material. Ordinary physical
purge, idempotent receipts, source evidence and recovery-ledger rules are retained.

Windows backup publication now flushes its staged file using a writable handle.
This corrects the file-descriptor error that previously prevented a local
workspace from saving its required backup before a schema upgrade. Backup
verification and refusal to replace an existing archive remain enforced.

macOS credential checks now use the asynchronous Keychain API with bounded
waits. A secure-store approval prompt no longer blocks the main app thread.
Locked saved connections remain visible, with **Retry secure storage** after
the operating system is unlocked. Local workspaces and temporary connections
can continue while saved credentials await approval.

## Service migration

The server requires the new checked database migration. Follow the
[withdrawal and upgrade guide](https://github.com/Perseusxrltd/mnemion/blob/v4.1.0/docs/service/withdrawal.md), preserve a verified
backup and current ledger, and use separate operator credentials for migration.
The existing automatic managed-patch policy does not apply changes across minor
versions or database schemas. Desktop clients and shared hosts still have
separate update ownership.

The [validation record](https://github.com/Perseusxrltd/mnemion/blob/main/docs/validation/2026-10-12-author-withdrawal.md)
records completed and pending acceptance. Published downloads are on the
[product page](https://www.perseusxr.com/mnemion). The
[roadmap](https://github.com/Perseusxrltd/mnemion/blob/main/docs/ROADMAP.md) retains
individual sign-in, invitations, independent host operations and recovery work.
