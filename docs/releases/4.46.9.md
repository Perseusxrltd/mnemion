# Mnemion 4.46.9

This candidate retains the [managed backup-capture correction](../validation/2026-10-25-host-backup-capture.md)
from the unpublished 4.46.7 and 4.46.8 candidates. Snapshot and access-ledger
captures wait up to five minutes to acquire the host lock while active scans
finish naturally. Before capture, they refresh settings, reject a runtime
transition during the wait, and recheck output destinations.

Windows release validation now accepts fragmented LF or CRLF readiness lines
from Python test helpers. Helpers have bounded lifetimes and close before
SQLite fixtures are removed; the desktop npm test step has a ten-minute limit.
All checks remain enabled. See the [Windows validation report](../validation/2026-10-25-windows-telemetry-test-lifecycle.md)
for the original timeout and focused correction evidence.

The optional [collector service](../implementation/anonymous-product-telemetry-collector.md)
uses a validated systemd socket handoff and denies process connect/bind calls.
Both service and socket must be stopped together. Product telemetry remains
disabled and incomplete, with no production destination or route selected.

Native release, publication and installed acceptance remain pending at this
source checkpoint. Use the automatic [release status](../RELEASE_STATUS.md)
for current availability.
