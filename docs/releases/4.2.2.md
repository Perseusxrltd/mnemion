# Mnemion 4.2.2

Task IDs, quote numbers and exact filenames now supply their own search
candidates. A matching file can appear even when its body omits other query
words or semantic ranking would leave it outside the candidate window.
Matches in the subject or file path receive higher priority than body-only
mentions. The app explains exact matches under **Why this result?**

The extra channel makes one scoped database query and no additional model
calls. It checks up to eight distinct literal identifiers, counts repetition
once, and rejects near matches such as `TASK-73120` for `TASK-7312`.
Windows/Unix path separators and NFC/NFD filename forms are supported.
Current permissions, source removal, quarantine, corrections and historical
filters still govern every candidate and citation. A correction observed
between candidate queries discards the old revision's ranking evidence.

Ordinary prose queries and explicit semantic-only searches retain their
existing ranking. The optional API ranking details preserve existing client
fields. See the [retrieval guide](../service/retrieval.md) for weighting and
bounds, and [validation](../validation/2026-10-13-exact-identifiers.md) for
regression evidence and its limits. General natural-language quality,
recency and no-match thresholds remain separate work.

There is no new database migration after 4.2.0. A host still on 4.1.x needs
the [guarded schema upgrade](../service/managed-upgrades.md) before compatible automatic patches can apply.
