# Mnemion 4.30.2

Recover encrypted server backups through **Recover a workspace** in the app.
Review the included or newer access ledger, preserve organization and memory
identities, and restore into a separate local database with fresh administrator
access. Host/provider configuration remains a separate recovery step. This
carries the feature from the unpublished 4.30.0/4.30.1 candidates.

Fix Windows database backup and restore file arguments at and beyond 260
characters. PostgreSQL now uses Windows extended-length paths for these files,
without changing registry settings or moving private temporary data. The app
and private agent status also retain bounded failure diagnostics for support.

Protect assistant-configuration backups and replacements on Windows. The
`mnemion-agent` setup tool now creates both files with explicit private
ownership and access permissions before writing configuration bytes. This
also protects any other providers' settings carried in the backup.

Existing policies, project trust settings, other MCP servers and TOML comments
retain their previous behavior. Failed replacements preserve the original and
its completed backup; an occupied staging filename is retained. POSIX private
permissions continue to apply on macOS and Linux.

Native Windows path and file-ownership checks, the focused agent-setup checks,
and a real database restore with later deletion/access reconciliation passed.
Installed-platform acceptance and public automatic updates remain separate
release gates. No database migration or new dependency is added.
