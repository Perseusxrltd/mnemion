# Mnemion 4.0.9

Desktop Studio can securely remember team workspaces and reopen them after an
app restart. The connection screen explains the identity, device storage and
session choices, and remains usable on narrow windows.

## Changes

- Remember connections with Windows protection, macOS Keychain or a supported
  Linux keyring. Do not fall back to plaintext keys when secure storage is absent.
- Use direct current-user protection on Windows, so an immediate crash cannot
  lose access to a newly remembered connection before Chromium saves its profile.
- Keep the real credential in the main process after connection. Give the
  interface an opaque handle restricted to that workspace's origin and API path.
- Recheck identity before restoring a saved connection. Refuse revoked keys,
  changed identities and altered saved destination metadata.
- Show saved workspaces, support keyboard opening and confirm device-only
  forgetting. Disconnect clears the live session and durably pauses reconnection.
- Preserve a later workspace choice when an earlier connection is slow. Let a
  user stop automatic reconnection and focus the new address field.
- Bound and atomically replace private connection data, serialize concurrent
  changes, and reject corrupt or unsafe files without silently replacing them.
- Offer an explicit, confirmed device-connection reset for damaged settings,
  preserving server data and refusing linked or foreign-owned files.
- Keep browser keys in window memory. Explain native session-only behavior and
  bundle the new [workspace guide](../service/workspaces.md) and updated privacy
  documentation.
- Extend the native release gate to real authenticated HTTP through the sandboxed
  bridge, an actual app process restart, OS-encrypted reconnection and Linux
  keyring/unavailable-keyring behavior.

## Compatibility and scope

No database migration, embedding change or reindex is required. Existing API,
MCP and Obsidian behavior is retained, together with the 4.0.8 Studio design and
independently signed Linux/macOS service updater. A saved desktop connection is
not a host-administration credential.

This is one part of complete app onboarding. A fresh standalone installation
still needs an existing service or operator setup. Native database/runtime
provisioning, provider sign-in, broader host controls, remote access and hosted
OAuth remain on the [roadmap](../ROADMAP.md). OS publisher limitations are unchanged.

## Validation

Local desktop policy/storage tests passed **47 checks**. Native Windows helper
checks verified decryption in a separate process and rejection of modified
ciphertext without a Chromium profile. Browser walkthroughs
covered a real PostgreSQL-backed connection, disconnect, remote-HTTP rejection,
saved cards, locked storage, expired keys, cancelled reconnection and 360-pixel
layouts. The real packaged Linux app authenticated through the new main-process
broker, saved a memory to PostgreSQL and cleared its session on disconnect. A
separate packaged process-restart test verified that unavailable Linux keyrings
leave no saved key and that stale/origin-mismatched handles are refused.

The native encrypted-restart matrix and full product release gates remain
mandatory before publication. Final evidence and public upgrades are recorded
in the [validation report](../validation/2026-10-11-hotfixes.md); a local fixture
does not establish every OS or company-device policy.
