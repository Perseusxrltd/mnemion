# Mnemion 4.46.51

Backup status can now follow a metadata file that is replaced atomically while
the app reads it. The reader verifies the replacement independently and allows
one fresh read, so an overlapping backup or settings save does not by itself
cause a safety error or return the replaced document. Unsafe permissions,
in-place changes, invalid JSON and repeated replacement still stop the read
without changing recovery files.

The [focused backup qualification](../validation/2026-10-29-backup-read-snapshot.md)
passed 33 checks on Linux, with one native-Windows-only check skipped. Native
installed qualification and publication for this version remain pending. The
original 4.46.50 Linux installed failure is retained; its exact cause has not
been established by these separate regressions.

This release also includes the
[joint telemetry-report consistency checks](../validation/2026-10-29-telemetry-joint-consistency.md)
prepared in 4.46.50. Estimates are withheld when their confidence intervals
cannot describe categories totaling 100%. Production telemetry remains off
while full acceptance is unfinished. The downloaded-installer limit remains
400 MiB, and the [field-readiness record](../implementation/multi-agent-field-readiness.md)
tracks the remaining shared-host and connector work.
