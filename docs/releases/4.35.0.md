# Mnemion 4.35.0

**Unpublished source milestone, superseded by [4.37.0](4.37.0.md).**

## Keep busy source imports from monopolizing indexing

A large import could leave another space's new memories, and physical purge
jobs, behind the entire older queue. This release changes the next-job selection:

- Pending purges take priority, including when inference is paused or the
  requested model is unavailable.
- Indexing alternates between eligible organizations, then between their spaces.
  An organization with many source spaces cannot take every organization's turn.
- Dispatch turns persist across worker restarts and use a database sequence, so
  clock corrections cannot give one queue permanent preference.
- Work within a space retains its existing order. Active leases, source-access
  checks, model approval, candidate-index rules and permission boundaries remain.

This advances the [indexing and bandwidth controls](../service/indexing-queues.md)
after [the live update lab exposed an existing backlog](../validation/2026-10-20-433-live-updates.md).
It does not interrupt a model calculation already in progress or promise a fixed
indexing latency for every model and workload.

**Schema migration `029_fair_indexing.sql` is required.** Back up the workspace
and use the [managed upgrade procedure](../service/managed-upgrades.md) for a
server, or the native app's normal guarded migration. Compatible automatic
hotfixes resume afterward. Model fingerprints and existing vectors are unchanged;
no reindex or new dependency is required.

[Focused validation](../validation/2026-10-20-fair-indexing.md) and native release
publication are separate gates. See [release status](../RELEASE_STATUS.md) for
available installers.
