# Mnemion 4.43.0

Let waiting semantic requests run between batches of long local document indexing.
The previous document-wide execution lock could keep a query waiting until its
admission deadline expired, even though individual inference batches had finished.

- **Cooperative indexing:** completed batches give existing queued work a turn,
  in arrival order, while retaining the document's original admission slot.
  Only one native inference executes at a time.
- **Adaptive CPU batches:** indexing begins with one chunk and uses measured
  execution time to target approximately 250 ms per batch within the existing
  RAM limit. The target does not interrupt a native call or guarantee latency.
- **Safe resumption:** tokenizer locks are released before yielding. The model
  and RAM policy are rechecked afterward, including model eviction or a changed
  memory budget. Model generations, evidence spans and broker ownership remain
  intact; existing indexes do not need rebuilding for this scheduling change.
- **Bounded waiting:** new requests keep the existing admission deadline.
  A document has a cumulative 30-second allowance for cooperative waiting;
  timeout leaves indexing retryable and cannot release another caller's lock.
- **Native setup diagnostics:** a missing-field timeout now retains a fixed
  selector, setup-step number and bounded route category in the installed-test
  artifact, without input values, page text or arbitrary URLs. All acceptance
  checks and deadlines remain unchanged.

Seventy focused checks passed. In one offline, pinned-BGE CPU comparison over
512 synthetic chunks, a concurrent query changed from HTTP 503 after 2.000 seconds
to success in 0.269 seconds while indexing continued. See the
[full measured validation](../validation/2026-10-20-inference-fairness.md) for
indexing time, process RSS, exact output parity and limits.
