# Mnemion 4.30.1

Recover an encrypted server backup through **Recover a workspace** in the
desktop app. Review its database and choose the included access ledger or a
newer encrypted ledger, then create a separate local workspace with preserved
organization/memory IDs, reconciled denials and fresh administrator access.

The app explains which server settings need separate setup before recovery:
source runners, provider credentials, company sign-in, cloud models, vault host
keys and network/OS settings remain in the original encrypted package. Existing
workspaces and backup files are retained. The same workflow is available to
authorized local agents through the private desktop controls.

This carries the 4.30 implementation. The unpublished 4.30.0 candidate was
withheld after two test fixtures failed in the full shared-database suite.
The corrected fixtures compare the complete multi-organization inventory and
write large ledger fixtures independently of the small settings-file limit.
The runtime's validation and recovery behavior are unchanged by that correction.
The native installer fixture also creates its temporary profile with explicit
current-user ownership on Windows; production folder-ownership checks remain intact.

No new database migration beyond 4.29, paid service or cloud-model call is added.
