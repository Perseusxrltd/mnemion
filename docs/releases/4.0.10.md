# Mnemion 4.0.10

Explore shared memory in a live 3D map and diagnose workspace connection failures
without exposing credentials. Studio uses the same connected M mark as the
Perseus XR product page across its interface, desktop icons and system tray.

## Changes

- Add the [live memory map](../service/memory-map.md) to browser and desktop
  Studio: stable 3D orbit/zoom, full-screen viewing, creator/time/type filters,
  focused connections, original evidence and a keyboard-accessible node list.
- Show actual creation, revision and review events to authorized reviewers.
  Organization administrators can resolve creator IDs to person/application
  names. Geometry is never presented as a truth or similarity score.
- Refresh authorized snapshots every 20 seconds while visible; support pausing,
  hardware-informed compact defaults, explicit record/node limits and a 2D mode.
  Stop drawing while idle. Clear the graph when refreshing access is rejected.
- Preserve the wiki, previous evidence graph, curation, Markdown and Obsidian
  workflows. Keep memory/source links accessible from the map.
- Add `mnemion-control doctor`: bounded health, readiness, identity, space access
  and MCP checks with a content-free JSON report. Detect offline ngrok tunnels,
  redirect/proxy problems, TLS/network errors and rejected credentials separately.
- Improve offline-tunnel errors in Studio and both SDKs. Accept API `/v1` and
  MCP `/mcp` addresses in the Studio connection form. Bundle a
  [connection/recovery guide](../service/connection-diagnostics.md).
- Generate every native/browser logo asset from one canonical SVG. Verify the
  asset hashes, preserve SVG bytes on Windows, include them in container builds
  and serve the web favicon/Apple-touch/brand assets explicitly.
- Keep read-only map filters from blocking automatic desktop restarts while
  retaining unsaved-draft and active-transfer protection. Extend the native
  packaged guard check to cover both cases.
- Add the [complete product requirements](../PRODUCT_REQUIREMENTS.md), current
  agent-platform research and updated in-app documentation.

## Compatibility and scope

No database migration, reindex, model change or new provider account is required.
Existing API keys, saved workspaces and tenant/space permissions remain valid.
The map requires a reachable workspace and displays bounded snapshots, not a
sub-second event stream. The diagnostic does not restart a remote host or grant
operator access through a memory key.

Native local hosting and complete fresh-machine onboarding, individual hosted
sign-in/OAuth, broader provider capture, graph time replay and larger-workspace
subscriptions remain on the [roadmap](../ROADMAP.md). The separate public Linux
x64 4.0.8 → 4.0.9 restart investigation remains open; this patch does not claim
that investigation resolved. Free publisher-signing limitations remain as
described in [code signing](../CODE_SIGNING.md).

## Validation and availability

The [validation report](../validation/2026-10-11-memory-map.md) records real
PostgreSQL/API browser and Linux Electron journeys, real live writes, revoked
access, idle rendering, full-screen viewing and update-draft protection, along
with unit and SDK checks. The release workflow requires product checks, all six
native installer/update gates and verified signed artifacts before publication.

Use [the official product page](https://www.perseusxr.com/mnemion) for currently
published downloads. Its version, downloads, checksums and documentation follow
verified releases automatically; a repository version bump is not publication.
