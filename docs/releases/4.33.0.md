# Mnemion 4.33.0

Configure your own embedding and librarian models from **Setup & this device →
Your model providers**, including local Ollama, compatible local servers and
cloud/organization endpoints. The built-in CPU models remain available.

Review the endpoint, model revision, dimensions and limits, then save. Private
keys and optional organization CA certificates stay with the host's OS account.
Changes drain and restart a running local host; saved settings are checked before
it reopens. Offline local setup and the private `local.models` agent operation
provide the same controls.

Enrollment makes no provider calls. Each space still chooses its embedding
candidate or librarian, approves outbound processing, and controls budgets.
Removal preserves memories/indexes; malformed settings have a reviewed repair
path that preserves the original private file.

The shared embedding queue now respects the smallest approved endpoint limit,
instead of replacing that limit with a larger process-wide default. Active
inference remains serial and excess requests receive a bounded busy response.

Desktop agent connection names and model profile IDs use browser-compatible
validation, including names containing hyphens.

External model-server RAM belongs to that server. Profile credentials use
OS-account file permissions, not keychain encryption. Native database backups
do not bundle this private provider configuration or its keys; recovery requires
re-enrollment and review. Provider-account enrollment, automatic model downloads,
live vendor certification and comparative model-quality recommendations remain
separate roadmap work.

No database migration or dependency is added. See the
[setup and recovery guide](../service/desktop-models.md),
[validation](../validation/2026-10-20-desktop-models.md) and
[published release status](../RELEASE_STATUS.md).
