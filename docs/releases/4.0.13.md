# Mnemion 4.0.13

Published for Windows, macOS and Linux on x64 and ARM64. Native release checks,
signature/inventory verification and all six public desktop upgrades passed.
The original shared server also completed its signed automatic patch. The actual
Windows app installed and relaunched this update after its ordinary idle period,
preserving the human administrator connection and background/startup settings.
See the [publication and live-update evidence](../validation/2026-10-12-v413-release.md).

## App and workspace server versions

**Setup & this device** shows this app's version separately from the connected
workspace server. **Refresh server** makes an authenticated check. Older services
that do not report their version remain usable and display **Version not
reported**; a failed check is shown separately and preserves the saved connection.
The screen links to the update and host administration guide.
Setup also uses the shared page spacing at desktop and phone widths.

An organization can update its desktop clients while its shared server remains on
an earlier release. Desktop updates apply to that device; the shared host needs
its own operator or managed service update. The new display makes those separate
lifecycles visible without requiring organization-administrator access.

## Compatibility

Connection diagnostics now accept spaces an organization administrator can see
without a memory-content grant. Earlier diagnostics incorrectly called this a
malformed server response and skipped MCP checks. Reports distinguish visible
spaces from `accessible_count`, continue checking MCP, and keep `no_spaces` when
there are no explicit content grants. This does not broaden anyone's permissions.

`GET /v1/me` adds `service_version` to the authenticated identity response. The
Python response contract and TypeScript client treat it as optional for earlier servers. The
reviewed agent contract and OpenAPI schema include it. There are no new database
migrations, model changes, keys, grants or paid dependencies.

An adopted 4.0.12 Linux/macOS Python service remains eligible for the existing
signed patch policy when its migrations and embedding identities match. A
4.0.0 shared service still requires a coordinated migration before adopting that
policy. Updating the desktop does not perform this migration.
