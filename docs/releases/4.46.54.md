# Mnemion 4.46.54

Source synchronization now explains the first selected file it cannot read in
Studio's file status, using a fixed error category and a source-relative path.
An incomplete scan does not treat unvisited files as deleted.

Previously indexed files that the failed scan could not re-read remain withheld
from recall and background embedding until a later scan reads them again.
Refreshing the source's access lease alone cannot restore those files. Readable
neighbors can continue indexing, and an unchanged file becomes eligible again
after a successful read. These changes address the permission and incomplete
inventory failures in [issue 47](https://github.com/Perseusxrltd/mnemion/issues/47).
The [source-read qualification](../validation/2026-10-29-source-read-diagnostics.md)
records the retained failures, recovery checks and native Windows evidence.

Windows checks the actual opened file handle and rejects name redirects. Cloud
file metadata is distinguished from symlink and junction tags; provider access
and hydration failures still surface as read failures. A synthetic cloud-tag
check is not a claim that every cloud provider was tested.

This batch also carries the [4.46.53 corrections](4.46.53.md) for Mac framework
launch compatibility, concurrent Windows backup-state reads and atomic process
test markers. Native qualification and acceptance on the affected machines
remain separate from source review. The latest
[MemPalace comparison](../research/2026-10-29-mempalace-product-review.md) records
the current product differences and the improvements worth adopting.

V08 remains Building. Production product telemetry remains disabled; the
reporting-backend work does not yet provide live fleet statistics. All 66
requirement states remain unchanged, and open issues retain their outstanding
field acceptance. Published installers and update availability are recorded in
[release status](../RELEASE_STATUS.md).
