# Mnemion 4.0.6

Python release packages now include a ready web Studio with offline documentation.
This addresses issue 7: an official package starts the UI alongside the API, and
a Git checkout has one explicit build command instead of several undocumented steps.

## Changes

- Include the matching web build, guides, roadmap and dependency license texts
  in both the Python wheel and source archive. No Node.js installation is needed
  to serve the packaged UI.
- Add `mnemion-service studio status` and `mnemion-service studio build`. Source
  builds use locked dependencies and Node.js 22+ with npm on Windows, macOS and
  Linux. They require no database or model-provider credentials.
- Discover the bundled UI by default; retain explicit `--studio`/environment
  overrides, and add `--no-studio` for an intentional API/MCP-only service.
  An unbuilt source installation prints the build command at startup.
- Validate bundle version, file paths, hashes, sizes and license inventory.
  Build fully before replacing the generated source bundle; failed replacement
  restores the previous bundle. Concurrent builds cannot share the checkout.
- Include repository documentation in the container build. All Studio builds
  now check for the essential offline guides and current release notes.
- Fix the container API entry point's reference to a retired model helper.
  It now runs the maintained offline model-preparation command before listening,
  and a failed model check keeps the listener closed.
- Require both Python artifact formats to contain identical verified Studio
  files in product CI and the release gate.

## Upgrade

This patch has no new database migration, embedding change or reindex requirement.
Upgrade the Python package and restart the API to serve its new UI. A Git checkout
should run `uv run --no-sync mnemion-service studio build` before restarting.
The build command does not restart services or replace a database. Existing
explicit Studio paths retain priority; remove an obsolete override to use the
bundled version. `mnemion-service studio status` identifies the selected build.

If upgrading from before 4.0.5, follow that patch's coordinated server migration
and backup instructions first. See [service setup](../service/README.md#studio),
[4.0.5 migration and rollback](4.0.5.md) and [desktop updates](../service/updates.md).

## Validation and remaining work

The local service group passed 245 tests with two skips and 84.91% coverage before
the final container fix; the final deployment/web group passed eight tests.
Thirty-three web bundle/artifact checks passed. Focused checks cover missing/altered assets, wrong versions, path traversal,
missing notices, failed replacement, concurrent builders, Windows npm paths,
default HTTP serving, disabled UI and continued API authentication. Product
checks build and inspect the real wheel and source archive; native release
gates remain mandatory before publication. The installed wheel's web UI, offline
guides, narrow layout and authentication were checked in a real browser.
The [dated validation report](../validation/2026-10-11-hotfixes.md) records
observed results and the preceding six-platform public automatic upgrade.

Managed server updates, non-systemd supervision, hosted-agent OAuth, remote
setup, further memory reductions and retrieval evaluations remain on the
[roadmap](../ROADMAP.md). This patch does not install or automatically update a
separately deployed memory server. OS publisher-signing limitations are unchanged.
