# Mnemion 4.0.12

This patch fixes desktop connections through free ngrok gateways. A recovered
workspace could remain marked offline because Chromium reused an old HTTP
response; a fresh request could then receive ngrok's human browser warning
instead of the Mnemion identity. Desktop workspace requests now bypass that
warning and HTTP caching, including subsequent API operations.

Connection diagnostics also support gateways that require a credential for
health checks. They retry an HTTP 401 once at the same destination with the
supplied key. Anonymous checks report `authentication_required` instead of
claiming that a key was rejected. Public routes and known offline tunnels still
receive no credential.

Authorization, destination validation, TLS verification, redirect rejection,
bounded responses and operating-system credential protection are retained.
This patch does not make a sleeping host available or promote a member to an
administrator. The host's independent operator controls remain necessary.

Validation: 16 diagnostic tests, the complete Electron unit suite, an actual
Windows Chromium reproduction of stale offline caching, immediate rejection
after credential revocation, blocked credential redirects, and successful
identity verification against the authorized live workspace. Its separate
Windows diagnostic completed 40 bounded lexical searches without memory writes
or model calls. See the [evidence and acceptance limits](../validation/2026-10-11-workspace-gateway.md).

The [product page](https://www.perseusxr.com/mnemion) lists published artifacts.
Release preparation does not establish that a particular installed app has
received the patch. Follow [connection and recovery](../service/connection-diagnostics.md)
and the [roadmap](../ROADMAP.md) for the remaining organization continuity work.
