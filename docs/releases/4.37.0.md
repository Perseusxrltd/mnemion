# Mnemion 4.37.0

## Reliable setup and fair, visible background work

Local setup status now tolerates the brief publication of a new private settings
file. Readers wait up to 310 ms for its temporary second name to disappear;
persistent links remain rejected, and the opened file is checked again before
reading. This corrects a reproduced startup error that could tell users to
choose a folder without links during otherwise ordinary setup.

Background cleanup takes priority over queued indexing. Organizations and their
spaces receive persistent indexing turns, so one large import cannot keep taking
every available turn. Active work is not interrupted, and existing model
approvals, leases, retries and access rules remain.

**Insights → Sources & pipeline** separates outstanding indexing and physical
cleanup, with pending/leased/failed counts, due jobs, retries, oldest age, total
waiting text and largest input. The same scoped metrics are available to agents
and exports. Text size and due counts are observations, not time or RAM forecasts.

**Schema migration `029_fair_indexing.sql` is required for older servers.**
Use the [backed-up, guarded upgrade](../service/managed-upgrades.md); the model
fingerprint is unchanged and existing embeddings need no rebuild. The desktop
continues through its normal protected update and migration path.
