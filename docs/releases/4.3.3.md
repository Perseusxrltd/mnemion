# Mnemion 4.3.3

Natural-language questions now receive bounded key-term support when hybrid
search finds no complete text match. Relevant documents can gain priority
without repeating the whole question. The app explains which terms matched;
users and agents can disable the behavior. Exact IDs, explicit search syntax,
source permissions and similarity thresholds retain their existing rules.

The evaluation lab now saves question-term, recency and archive preferences
with each run. Teams can compare these settings on their own test sets. New
runs record the executing service version and stop if a hotfix would mix
implementations within one run. Existing clients and saved run configurations
remain compatible.

A [60-question regression](../validation/2026-10-14-question-retrieval.md) with
the pinned local CPU model improved Recall@5 from 90.3% to 95.2%, with median
search time increasing from 192 to 213 ms. This reuses an existing benchmark;
it is not a new held-out or universal quality claim. Broader natural-language
retrieval, dated-section handling and live shared-workspace acceptance remain
open under issues 17 and 31.

No database migration, forced re-index or additional model call is introduced.
See the [retrieval guide](../service/retrieval.md#natural-language-question-support),
[evaluation guide](../service/insights.md) and [release status](../RELEASE_STATUS.md)
for controls, validation and actual publication.
