# Mnemion 4.46.39

`mnemion split` now preserves sessions whose generated filenames collide. It
chooses another name and creates each output exclusively, so an existing file
or a competing writer's file is preserved. Missing output directories are
created when applying the operation; transcript input and output use UTF-8.

Each original transcript is archived in a newly reserved
`.mnemion-split-backup-*` folder beside its source, keeping its `.mega_backup`
filename. The command prints the full backup location and preserves older
backups. Dry runs create no output or backup directory. If a write fails, the
original remains available for recovery; an interrupted archive move preserves
the original either in place or in its new backup. Partial output files can
remain after an I/O failure. The [splitting guide](../guides/transcript-splitting.md)
explains preview, backup locations and recovery.

The desktop also reuses a confirmed telemetry opt-out as a bounded negative
hint, avoiding a duplicate SQLite read. Fresh consent, collection and delivery
checks remain authoritative. Production product collection remains **disabled**
while full resource, privacy, runtime and platform qualification continues.

The [splitter validation](../validation/2026-10-27-split-preservation.md) records
72 passing source checks, including filesystem collisions, interrupted work,
preview and classic CLI behavior. The [opt-out validation](../validation/2026-10-27-telemetry-disabled-hint.md)
retains 116 passing Electron component checks and two Windows-only skips.
