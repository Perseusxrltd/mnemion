# Mnemion 4.1.6

Git imports stop revising unchanged memories on unrelated repository commits.
Each document now retains the commit of its own last path change, together with
its blob and immutable evidence link. Changed, renamed and deleted paths keep
the existing complete-inventory and access rules. This avoids unnecessary memory
revisions, timestamp changes and embedding work. Existing imports may refresh
their older commit-wide provenance once on the first scan after upgrading.
The connector still performs a complete inventory; this is not a delta-only
network synchronization protocol.

Managed connector reports now distinguish the initial `startup`, scheduled
`poll` and user/agent `requested` scans. The reason survives update waits and
compatible launcher handoff. Restoring an older runtime remains supported,
including that runtime's older diagnostic behavior.

MCP agents can call `memory_search` or `memory_context` with just a query, and
`memory_map` without a space list. Omitted spaces default to everything that
caller can currently read, including connected sources. Explicit IDs narrow the
scope; an inaccessible space or invalid combination never falls back to a wider
search. Explicit `[]` still requires `all_accessible: true`. Saves always need a
writable space. The HTTP API retains explicit scope selection.

Both small health responses now include the running API's `service_version`.
Private connector and update details remain in authorized host status. The
[connection guide](../service/agents.md#migrating-a-separate-mcp-listener)
also explains retaining a standalone port 7893 listener or moving existing
clients to the combined port 7892 endpoint.

See the [validation record](../validation/2026-10-13-agent-ingestion-stabilization.md),
[source guide](../service/connectors.md) and [agent guide](../service/agents.md).
These changes address issues 23, 24, 29 and 30. No database migration or model
download is required. The gateway and connector must be updated to receive their
respective fixes; a desktop update does not implicitly update a separate server.
