# Mnemion 4.17.0

Live agent conversation capture gets a dedicated JSONL adapter. It captures
complete records in bounded fragments, waits for unfinished tails and gives each
file its own source controls. A failing transcript no longer suspends unrelated
files in this adapter. This addresses the live-file failure described in issue 41.

- Long files stream through configurable record, fragment, file and time limits;
  the ordinary text adapter's 20 MB default does not apply to this source type.
- Private metadata checkpoints reuse verified older fragments. Unchanged files
  need no content reads; appends recheck the older prefix and process the final
  fragment plus new records. Only new or changed evidence needs a body upload.
- Body-free connector references retain an exact existing source revision without
  recreating deleted memories, overriding corrections or replacing proposals.
  Checkpoints advance only after a complete service acknowledgment.
- Source offsets, segment hashes, raw records and readable conversation fragments
  retain provenance. Codex headers and explicit ACP event identities survive
  segment boundaries. Rendered fragments do not claim whole-session turn counts.
- Studio adds the source choice, configuration template and per-file captured,
  pending, source-read and fragment-reuse counters. The same completed checkpoint
  is available to authenticated agents through existing connector scope routes.
- Source replacement, truncation, rename, deletion, access loss and incomplete
  directory inventories retain distinct handling. Git memory journals must keep
  using the complete journal connector; they are rejected by this live adapter.
- Quitting or updating the desktop waits for independent local control processes
  before draining the database. A bounded failure keeps the app open. Native
  acceptance reports now include safe phase, exit/signal and shutdown-state
  diagnostics without uploading workspace contents or credentials.

The source is opt-in and uses an explicitly mapped audience. Upgrade both server
and runner to 4.17.0. Prefix verification still reads old bytes when a log grows;
this release does not claim zero disk I/O for appends or native hooks installed
automatically. Oversized individual records and scan-budget exhaustion remain
visible per-file failures. No personal history is selected automatically.
