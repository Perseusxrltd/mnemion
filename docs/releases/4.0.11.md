# Mnemion 4.0.11

Create a private memory workspace directly in the desktop app, with its own
database and CPU model. Control its RAM budget, recover an occupied local address
and keep the same memories and credentials across app restarts.

The [official product page](https://www.perseusxr.com/mnemion) lists verified
published downloads. Availability requires the complete native release gates
and publication; a source version change alone is not a published download.

## Changes

- Bundle the local service, PostgreSQL 18.6, pgvector and CPU inference runtime
  with the desktop installer. Guided setup creates a private workspace, downloads
  the chosen model, verifies actual save/search and reopens it after restart.
  Users do not need Python, Docker, a compiler, a GPU or a paid account.
- Offer automatic hardware-aware or explicit RAM budgets, current resource use,
  smaller indexing batches, pressure-aware model admission and idle unloading.
  Local agents can inspect and change the same policy. The budget is cooperative;
  it is not an OS-enforced memory reservation or absolute process limit.
- Recover a damaged RAM policy through the app or a typed operator command,
  retaining private damaged bytes and refusing stale or unsafe replacements.
- Recover an occupied local API port with automatic or exact port selection.
  Preserve workspace identity, keys, models and RAM settings; refresh concurrent
  changes before saving and explicitly Resume after the repair.
- Serialize local settings changes with startup, shutdown and app replacement.
  A cancelled update reopens only a workspace it actually stopped, and an
  explicit pause or app exit cancels deferred reopening.
- Fix a Linux automatic-restart stall caused by Electron retaining focus on a
  hidden, minimized window. Keep ten-minute inactivity, unsaved-work and transfer
  guards. The controlled real-updater comparison passed both Linux architectures.
- Show the downloaded version and the reason a restart is waiting. Add
  **Restart to update**, retaining unsaved-work, transfer, shutdown and policy
  checks while allowing a deliberate restart without the idle/focus wait.
- Keep local address repair disabled until the failing engine finishes cleanup.
  Report bounded setup diagnostic codes and code locations without exposing
  database errors, credentials, source content or private filesystem paths.
- Fix native Windows startup rejecting its freshly migrated database because
  packaged SQL files use different line endings. Check the same UTF-8 SQL text
  used by migration, keep actual migration changes rejected, and package SQL
  with consistent line endings across platforms.
- Create independent organization administrators explicitly in People & apps,
  view their organization roles, issue individual keys and administer space
  grants. Open administration, source connections, setup and help without a
  memory-space grant. Ordinary identity creation still defaults to member, and
  administrators receive no automatic content access. Offline host recovery
  still needs independent operator access.
- Retire people or agents through a named confirmation in the app. Their keys
  and linked sign-ins stop granting access while recorded memories and history
  remain. Present the identity roster as readable cards on small screens.
- Reject removal of the final currently usable administrator credential. Serialize
  API and OAuth credential changes across a tenant, recheck authority and expiry
  after waiting, and retain normal key rotation and idempotent revocation.
  A remaining credential must still be held and tested by its owner; the guard
  does not establish host access or external identity-provider availability.
- Strengthen Windows database process identity checks to recognize equivalent
  paths while requiring the exact bundled executable. Keep user-only storage,
  TLS/SCRAM authentication and Unicode manifests. The native ARM app uses the
  verified x64 service/model/database through disclosed Windows compatibility.
- Require API and worker initialization receipts before accepting a managed
  service update. Preserve earlier readiness protocols for compatible rollback
  and keep accepted memory writes through runtime rollback.
- Add optional trusted-issuer OAuth resource-server support, discovery/challenges,
  bounded introspection and immutable, individually revocable identity bindings.
  The API/CLI/MCP catalog now exposes 87 operations. This is a foundation for
  organization identity, not a completed built-in sign-in or hosted-agent flow.
- Refresh setup, agent/operator, packaging, RAM, update, validation and roadmap
  documentation. Preserve existing shared-service connections, 3D knowledge
  views, source controls, librarian, evaluations and Obsidian workflows.
- Bound retries for temporary Windows installer locks during native-test cleanup.
  Both Windows architectures completed real installed workspace acceptance before
  this cleanup race was corrected; the final complete run remains the release gate.

## Installation and compatibility

The desktop targets remain Windows, macOS and Linux, x64 and ARM64. Windows ARM
has a native desktop/client and an x64 backend. Native Windows hosting requires
Windows 10 build 18362 or later (Windows 11 supported); macOS requires version 13
or later. Linux packages retain the Ubuntu 22.04 build baseline. First local
model setup needs internet access and disk/RAM headroom; existing team clients
can continue connecting without installing a model on each device.

Existing Studio connections and application keys remain valid. A desktop update
does not migrate a separately hosted service. Local data lives outside the
installation directory and is retained during replacement.

An affected older Linux AppImage still runs its old restart logic. Use one normal
**Quit Mnemion Studio** to apply an already downloaded update, or install the new
official download. A public unattended upgrade from a released fixed client to
a later patch is still required before closing issue 21; modified diagnostic
copies are not public-update acceptance.

## Shared-server upgrade and rollback

This release adds `013_oauth_bindings.sql`, without changing existing embedding
identities or requiring reindexing. The migration is required even when optional
OAuth configuration is disabled. **Upgrade the service, gateway, workers and
source runners together.** Managed service updaters intentionally hold a
changed-schema release for operator planning; they do not silently migrate it.

1. Retain the previous release environment and private deployment settings.
   Pause ingress and stop API/MCP, workers and ingestion before the final backup.
2. Create and verify a database backup and current deletion/access ledger using
   the existing [operator recovery procedure](../service/recovery.md).
3. Install this release's locked dependencies in a separate environment. Run
   `mnemion-service migrate` with the database-owner credential; API and worker
   processes keep their separate restricted logins.
4. Restart matching components, verify initialized readiness, scoped save/recall,
   grants and selected sources, then reopen normal access. OAuth is optional and
   requires explicit [host configuration and identity bindings](../service/oauth.md).

Do not run an older binary against the migrated database. Before new writes are
accepted, rollback can restore the verified prior backup into a separate
database with the previous recovery tools and current access/deletion ledger.
Keep the upgraded database. After accepting writes, preserve them and plan
recovery explicitly; silently reverting a snapshot would discard them.
