# Mnemion 4.46.25

Explicit selection of a saved workspace now distinguishes opening the same
profile from switching to another verified workspace/account. Local-to-saved
selections are handled in both app and native paths. The decision uses the
normalized endpoint, tenant and principal inside the existing connection
controller; a fresh session handle alone remains an open.

One original telemetry policy/generation snapshot and clock govern the action.
Only a one-use open/switch enum reaches its observation boundary; it is not added
to JSON or saved state. Both choices retain the existing accepted outcome.
Failed restores keep failed-open semantics, cloned or reused results cannot
prove a new switch, and automatic resume stays unowned. New connect, sign-in and
local-open actions keep their labels.

Explicit native/app backup inventory now owns `backup.list` when its bounded
controller operation succeeds. It does not imply backup validity, successful
restoration or cloud delivery, and telemetry does not inspect the list contents.
Status, polls and reusable helpers remain excluded.

The [source inventory](../validation/2026-10-26-telemetry-workspace-selections.md)
contains 94 categories, with 93 mapped and one unmeasured, and 632 declared
actions/fixed variants: 360 mapped, 265 excluded and seven delegated.
`update.verify` stays within the download cycle without a separate observation.
These mappings do not establish full interface, sensor or installed coverage.

[Source validation](../validation/2026-10-26-telemetry-workspace-selections.md)
passed 30 distinct Python cases, 69 compiled Node controller cases plus one
Node/Python SQLite policy integration case, and 25 browser-source cases. Both
builds passed, with no Node skips. Two initial Python coverage-fixture failures
are retained with corrections for a stale category total and collapsed restore
variants; only those cases reran, with no runtime correction. Earlier source and
release evidence remains historical. Release preparation, native qualification
and publication remain separate gates.

V08 remains **Building and inactive**, with collection unavailable and null
destination/route. Catalog, disclosure, wire format, all 66 requirement texts
and existing resource/privacy limits remain unchanged. Resource,
whole-wire/provider/ingress privacy and installed-platform acceptance stay open.
