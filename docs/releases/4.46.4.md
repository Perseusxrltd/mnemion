# Mnemion 4.46.4

This update disables legacy storage's vendor analytics and reduces the database
work needed to create and verify backup inventories. Publication, downloads and
platform qualification follow the [current release status](../RELEASE_STATUS.md).

Legacy Chroma clients now use an explicit no-op analytics client at every
production construction point. Environment settings cannot re-enable that
vendor client. A fresh real-storage subprocess test observed **zero vendor SDK
calls, zero network attempts and no new analytics identifier** after the fix.
The [privacy regression evidence](../validation/2026-10-23-legacy-vendor-telemetry.md)
records **52 focused checks**. This correction is separate from the requested
anonymous Mnemion product telemetry: **V08 remains Planned and inactive**.

Backup inventory queries compute the full collated JSON representation once.
A small second result column retains PostgreSQL's tuple-sort memory accounting,
so large inventories can spill to disk within the configured sort budget.
Existing backup formats, full-row coverage, byte ordering and SHA-256 hashes
are preserved, including tables without a primary key. The regression and
portability selection passed **9 tests**.

In [six synthetic PostgreSQL 18.6 comparisons](../validation/2026-10-23-backup-inventory-throughput.md),
the chosen query preserved every row count, byte count and digest, roughly
halved temporary sort space and reduced measured query/hash time. Sampled
backend RSS growth stayed about **2.25–3.32 MiB** at original and fourfold data
sizes with `work_mem=1MB`. These measurements cover inventory processing;
complete production backup and restore durations depend on the actual data,
host and storage provider.
