# Mnemion 4.46.64

Source connections now retain a useful, private diagnostic when a selected
directory becomes unreadable, is replaced by a link, or contains an unreadable
journal. The existing runner records the failed inventory and withholds
unverified memories in the same operation. A root-only permission refresh
cannot expose those memories; a complete successful scan restores access.
The app shows the stopping category, and an authorized agent can safely replay
the saved result without suspending another runner's lease.

Managed-host recovery also checks the configured Git cache before issuing
eligible source keys or preparing runners. Disabled or removed connections
cannot block a restore through an unused cache. Existing bare repositories,
working trees and directory symlinks retain their supported behavior, and a
restore paused at an unusable cache can resume after that same path is repaired.

The [source-access checks](../validation/2026-11-01-source-abort-diagnostics.md)
passed all 24 selected cases. The
[Git-cache recovery checks](../validation/2026-11-01-git-cache-restore.md)
passed all 22 selected cases across both key policies. These changes use the
existing scan and recovery operations and add no background worker or model
load. Actual platform builds, publication and automatic-update results are
tracked in [release status](../RELEASE_STATUS.md).

The [Mac diagnostic compilation report](../validation/2026-11-01-macos-keychain-compile.md)
also records successful Intel and ARM64 compilation. Real Keychain approval
retention remains open. All 66 product requirements retain their current
states; V08 remains Building and production telemetry stays off.
