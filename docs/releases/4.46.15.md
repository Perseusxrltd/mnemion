# Mnemion 4.46.15

This update adds bounded storage ownership and more accurate handling of
manually reviewed telemetry to the 4.46.14 changes. See automatic
[release status](../RELEASE_STATUS.md) for current availability and platform
qualification.

Selecting which randomized reports to send can distort feature percentages.
New **wire v2** prepares a fixed manual report before inspection, containing no
categorical measurement or random draw. Reviewed reports
contribute only to the coarse overall report-volume range; categorical estimates,
sample thresholds and precision use automatic reports. **Report v3** explains
that population and its assumptions. Immutable aggregate v1/v2 reports remain
readable, while incoming wire v1 is refused because it lacks a selection marker.
The body stays four bytes, with unchanged automatic randomization, thresholds
and budgets. Manual preview explains its fixed body and makes no participation
or human-selection privacy claim.
See the [original defect and source checks](../validation/2026-10-26-telemetry-review-selection.md).

Native telemetry now takes one nonwaiting storage slot before asynchronous
permission or SQLite work. Competing optional samples decline; only actual
connection closure releases ownership. Windows permission checks likewise
retain their helper until process exit, including after a timeout. Privacy
refresh uses one coherent response instead of launching two control requests.
The [32-call diagnostic](../validation/2026-10-26-telemetry-storage-slot.md)
reduced peak live handles from 32 to one, with later independent work succeeding;
it does not establish an RSS improvement. The shared-permission regression
fixture now explicitly applies mode `0755`, so a restrictive `0077` umask cannot
silently make its deliberately unsafe directory private. The corrected fixture
passed under `0077`; production permission checks are unchanged.

The Windows ARM delivery fixture now uses Python's normal runtime-clock loader
instead of loading the ARM64 Node helper into x64 Python. The original 4.46.14
job's **WinError 193** remains preserved. The corrected local delivery module
passed **17 checks without failures or skips**; product runtime code is unchanged,
and actual Windows ARM qualification remains pending at this source checkpoint.
See the [fixture follow-up](../validation/2026-10-26-telemetry-review-selection.md#windows-arm-runtime-clock-fixture-follow-up).

Final selection validation passed **149 Python, 113 browser-source and 41
native Node checks**, without skips. It covers constant manual bodies without
entropy, rejected malformed review packets, unchanged automatic estimates,
real TLS, cross-language parity and private SQLite review handoff. Electron and
frontend builds passed. The intermediate marker-only results and original
TLS-fixture failures remain preserved. No renderer benchmark or
installed-platform journey ran for these additions.

**V08 remains Building and collection unavailable**, with destination and route
null. All 66 requirement scopes and states are unchanged. The **2 MiB / 0.5%**
resource gates, interactive privacy, utility, whole-wire and full installed
qualification remain open. Frozen 4.46.14 is separate from this source work.
