# Mnemion 4.13.0

Rebuild a supervised Linux/macOS workspace host from an encrypted recovery
package while retaining its organization, memory and source identities.
The operator workflow restores a verified database, creates separate restricted
database logins, prepares the service and selected source runners, and resumes
after an interruption or loss of its installed runtime.

- `mnemion-service host` provides key creation, full snapshots, smaller current
  access ledgers, authenticated inspection, guarded restoration and status.
  Credentials use private files and never appear in the public recovery plan.
  Ledger capture also works with API-key schemas that predate individual sign-in.
- Default restoration rotates access. An explicit application-continuity policy
  retains only eligible non-administrator application keys supported by both the
  backup and current ledger. Revocations, expiry, later deletions and fresh vault
  grants remain enforced. Included revoked source keys are not replaced.
- Managed updates are the default for restored hosts and respect an explicit
  pause. Up to 64 registered source runners share Supervisor's lifecycle and
  follow the verified managed runtime. Status separates local readiness from
  unverified external transport and supplies the generated boot instructions.
- Replacement service logins can use a password-authenticated database endpoint
  independently of the cluster operator's socket/authentication. Operator
  passwords, passfiles, private client keys and role overrides are not retained
  in those service logins.
- Connector setup explains adapter names versus permission policies, catches
  mismatches before provider reads, and reports the required token-reference
  shape without exposing input values. Imports exclude recognized host recovery
  controls and Mnemion credential material, including renamed copies.

The [host guide](../service/host-recovery.md), available in app documentation,
provides custody, restore, source-path, key-policy and startup instructions.
[Validation](../validation/2026-10-19-host-recovery.md) records actual PostgreSQL,
process and CLI recovery evidence. This advances the
[host-reset report](https://github.com/Perseusxrltd/mnemion/issues/38); it does not
close all of that report's deployment and independent-custody requirements.

This batch adds no migration beyond the 020 vault schema introduced in the
[4.12 source](4.12.0.md), and no paid dependency. Installers for this version must
pass the normal native and public-update gates.
See [release status](../RELEASE_STATUS.md) for publication, not just source readiness.

Automatic verified off-host upload, guided host import in the app, Windows/Compose
host adoption, delegated host wake/takeover, and Git write-back remain on the
[roadmap](../ROADMAP.md). Existing desktop backup and recovery flows remain
available on Windows, macOS and Linux.
