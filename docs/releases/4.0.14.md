# Mnemion 4.0.14

This patch keeps Linux process readiness and live RAM status valid when a host's
clock changes, including a suspended virtual machine resuming. It retains
Windows, macOS and Linux on x64 and ARM64 and their existing update channels.
The [product page](https://www.perseusxr.com/mnemion) lists published downloads.
The [publication record](../validation/2026-10-12-v414-release.md) records all
30 release gates, all six public desktop upgrades, the original shared-host
patch and Windows administrator reconnection.

## Reliable process and resource observations

Linux readiness now uses the kernel boot identity and process start counter,
so the same running process is not mistaken for a replacement after a wall-clock
correction. Different processes, boot identities, runtime versions and model
generations still fail the readiness check. Invalid identity records do not
fall back to a weaker comparison.

The same protection applies to local RAM status. Fresh RAM samples also continue
when the wall clock moves backwards. Windows and macOS retain their native
creation-time identity check. Earlier records stay compatible with their existing
exact timestamp rule and are renewed by normal process startup.

## Compatibility and release evidence

No database migration, embedding replacement, key rotation, permission change or
new paid dependency is introduced. Managed Python patches remain subject to the
existing signature, schema, backup, startup and rollback policies. Existing
bootstrap code is retained; use the current verified runtime or operator package
to inspect the new Linux identity records.

The [host finding and validation](https://github.com/Perseusxrltd/mnemion/blob/main/docs/validation/2026-10-12-host-clock-readiness.md)
records the reproduced failures and current acceptance evidence. The
[roadmap](https://github.com/Perseusxrltd/mnemion/blob/main/docs/ROADMAP.md) and
[requirements checklist](https://github.com/Perseusxrltd/mnemion/blob/main/docs/PRODUCT_REQUIREMENTS.md)
retain sign-in, independent host operations and recovery work. This patch does
not make a sleeping computer or offline tunnel reachable.
