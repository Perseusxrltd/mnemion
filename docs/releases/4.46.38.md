# Mnemion 4.46.38

`mnemion repair --dry-run` now stops after checking the collection count. It no
longer extracts drawers, creates a backup or proceeds toward deleting and
rebuilding the collection. The global `--no-telemetry` option suppresses optional
product observations for one CLI invocation without changing the saved privacy
choice; automatic hook imports use it to avoid inferred, duplicate ownership.

The in-app telemetry coverage view now identifies 700 declared actions and
variants, including reviewed CLI ingestion, librarian, model-control, memory
review and wiki commands. It distinguishes previews and status reads from
applied work and leaves `split` and `llm test` visibly unmeasured. Commands whose
normal return cannot prove completion report an unconfirmed outcome. Private
queries, paths, memory contents and command results stay outside observations.

This release also carries the intervening telemetry source fixes: recoverable
setup controls, privacy checks before result inspection, cached fixed catalog
metadata, and delivery opportunities for previously queued reports after new
contributions are refused. Fresh opt-out, company restrictions and shutdown
remain authoritative. Production product collection remains **disabled**;
complete telemetry, resource, privacy and platform acceptance is still in progress.

The [CLI validation](../validation/2026-10-27-telemetry-cli-outcomes.md) records
128 distinct passing Python cases, the browser coverage-preview check and
SDK/frontend builds. The [CI selection validation](../validation/2026-10-27-telemetry-check-selection.md)
records 98 passing safeguards for faster component-only development checks;
every release still requires the full suite. See the automatically maintained
[release status](../RELEASE_STATUS.md) for public artifacts and platform results,
and the [roadmap](../ROADMAP.md) for remaining work.
