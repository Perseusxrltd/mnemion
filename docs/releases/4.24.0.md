# Mnemion 4.24.0

Recent search now respects archive preferences and retains useful keyword
support for multilingual questions. Comparable current sources precede archived
drafts, while strong historical evidence still precedes unrelated fresh notes.
Dates remain unchanged, strict date ordering remains available, and the app
explains the archive decision. Normal relevance search also preserves the sole
literal historical record when only generic semantic alternatives exist.

This addresses the archive, bilingual-question and mixed-decision-row patterns
in issues **17 and 31**. A reproducible 50-document check uses the shipped pinned
multilingual model, real PostgreSQL and explicit target labels, both before and
after indexing. With the complete index, the intended document is first in
13/13 relevance searches and 12/13 recent searches, and in the top four for all
13. These synthetic development cases are not a general accuracy guarantee.
[The evidence](../validation/2026-10-19-retrieval-archives.md) includes baseline
results, per-case data, remaining limitations and the command to repeat it.

This release also carries [KeePass transfer](../service/keepass.md) from the
withheld 4.23 candidate. Intel Macs use Argon2 bindings 25.1.0; other platforms
retain 26.1.0. Both vendor the same upstream Argon2 implementation. The selected
Intel wheel lets managed hosts install without a compiler. The release process
now checks binary availability before native builders start, and both Mac
architectures run the KeePass interoperability checks.

Evaluations record the retrieval implementation that actually starts, preserving
the earlier identifier when a queued run spans an upgrade. Running evaluations
continue to reject mixed service versions. No extra inference or re-indexing is
needed for these ranking changes. Existing access, deletion, source visibility,
score floors and source-group limits remain enforced.

There is no new schema migration beyond the KeePass migration 026 carried from
4.23. Current native availability and update checks remain the independent
[release gates](../RELEASE_STATUS.md). Issue associations close only after the
matching release is published and its required public checks pass.
