# Mnemion 4.3.0

Agents supporting MCP OAuth can now open Mnemion's own sign-in and consent page.
People use their personal workspace login, review the requesting application
and current permissions, and explicitly approve or cancel the connection.
The agent receives revocable access without receiving the person's password.
The [connection guide](../service/hosted-agent-sign-in.md) covers setup and use.

**Account & sessions → Connected apps** lists authorized applications, their
creation, last renewal, expiry and revocation. People can revoke their own
connections; administrators can inspect and revoke connections within their
organization. The API, TypeScript client and reviewed agent catalog expose the
same controls. The catalog now contains **102 operations**.

The optional authorization server provides discovery, public client
registration, S256 PKCE, exact callback and resource binding, one-use codes,
rotating refresh credentials and revocation. Consent is bound to the browser
and the reviewed permissions. Password reset, revoked authority and disaster
recovery cannot reactivate an old authorization. Request, registration, session
and password-work limits keep the flow bounded.

Enable built-in OAuth on one workspace behind its configured HTTPS origin.
Existing API keys, personal sign-in and external authorization-server mode
remain supported. This release requires **migration 016**. Bundled local
workspaces use the guarded desktop migration path; separately managed hosts
need the documented [backed-up upgrade](../service/managed-upgrades.md).
OAuth remains opt-in and needs no paid identity service.

The consent page follows the Studio theme, supports mobile scrolling and keeps
pending credentials in memory. Approval delegates the person's current account
permissions, including future changes. Use a separate account for a narrower
agent role; a per-connection space allowlist is not part of this release.

[Validation](../validation/2026-10-14-hosted-agent-sign-in.md) covers real
PostgreSQL authorization, HTTPS browser consent, MCP discovery, refresh,
revocation, replay, access boundaries and recovery. Live ChatGPT, Dot, Claude,
Grok Bot, Hermes and OpenClaw acceptance remains separate work, along with CIMD,
company SSO onboarding and guided host configuration. The
[complete requirements](../PRODUCT_REQUIREMENTS.md) retain that work.

Public upgrade checks now explicitly hand their final result to status
reconciliation, keeping release evidence and eligible issue closures current.
Public delivery and native acceptance are recorded automatically in
[release status](../RELEASE_STATUS.md).
