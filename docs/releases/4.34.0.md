# Mnemion 4.34.0

## Slack and Google Drive setup in Studio

Studio can run selected Slack channels and Google Drive files or folders from
**Connections → Run on this computer**. A local database is not required: the
computer can contribute to an existing shared workspace.

- Slack accepts an existing approved token, a workspace ID and selected channel
  IDs, with optional thread capture.
- Drive accepts a service-account JSON key and selected IDs or Google HTTPS
  links. Read-only access tokens are renewed in memory. No user impersonation or
  provider credentials are sent to the Mnemion server.
- The provider credential and dedicated Mnemion application key receive separate
  OS protection. Saving verifies both accounts before starting a scan.
- Imported access continues to follow actual provider permissions and explicit
  Mnemion identity mappings. Selecting a source does not grant its contents to
  every workspace member.
- Existing scan limits, RAM controls, background scheduling, offline pause and
  removal, and private agent controls apply to both providers.
- Setup reports invalid credentials, missing provider access and rate limits
  without showing credential values.
- Selecting a connection no longer leaves a false unsaved-edit flag that blocks
  automatic updates and private agent controls. Actual source drafts still guard
  both operations until saved or discarded.

See the [cloud source guide](../service/desktop-cloud-sources.md) and
[validation record](../validation/2026-10-20-desktop-cloud-sources.md).

This adds setup for existing organization credentials. Interactive Google OAuth,
Slack token rotation, provider-app enrollment and customer-account acceptance
remain separate roadmap work. Tests use controlled provider responses; they do
not certify a customer's Slack or Google account. There are no database schema
changes or new dependencies. Published installer availability remains in
[release status](../RELEASE_STATUS.md).
