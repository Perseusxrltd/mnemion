# Mnemion 4.46.5

Backup transfers retain clearer failure evidence and spend less time processing
encrypted files. Publication, downloads and platform qualification follow the
[current release status](../RELEASE_STATUS.md).

Before uploading, the host retains the exact delivery manifest and file hashes.
A bounded progress record identifies the most recent Git transfer stage. If a
transfer fails, its operation can retain a fixed failure category and exit code;
Host controls displays guidance without credentials, raw Git output or exception
text. The original operation remains unconfirmed until its outcome is inspected.
This release adds no automatic retry or resume action.

Git compression and delta search are disabled for encrypted backup parts, with
one packing thread. Four local trials against bare Git repositories preserved
every file size and digest while reducing mean processing time from **27.147 to
13.067 seconds** for a synthetic 64 MiB fixture. This measures local processing,
not network speed or complete production backup duration.

The [source validation report](../validation/2026-10-23-backup-transfer-diagnostics.md)
records **19 passing focused checks**, two local SSH-fixture skips, and a passing
frontend TypeScript/Vite build. Native packaging and public update acceptance
remain separate release gates. The earlier live backup failure remains recorded;
these source checks do not establish fresh backup delivery or independent restore.

[V08 anonymous product telemetry](../implementation/anonymous-product-telemetry.md)
remains Planned and inactive. The full requirement inventory and existing
deployment acceptance issues remain open where their outcomes are unverified.
