# Mnemion 4.3.2

Git connections now show the commit from their last completed scan in
**Connections → Source status**, the API/SDK/agent controls, ordinary scan
reports and managed host status. This addresses [issue 37](https://github.com/Perseusxrltd/mnemion/issues/37):
a bare cache's local `main` could stay on its original commit while the connector
correctly indexed a newer fetched snapshot, causing misleading freshness alarms.

The checkpoint advances only after a complete inventory. Failed or interrupted
scans retain the previous completed snapshot and its date. The scanned repository
commit is separate from each document's last-change commit, so unchanged files
retain their revisions and timestamps. Host status accepts a private receipt from
the matching completed scan; rollback to a runner without receipts shows unknown
provenance instead of reusing a stale receipt.

The update reuses existing checkpoint storage: no database migration, forced
re-index, provider permission change or Git branch rewrite. New fields are
optional for older clients and appear after the first complete upgraded scan.
The [connector guide](../service/connectors.md#git-snapshot-freshness) explains
how to compare the snapshot with the remote branch and distinguish source
ingestion, pending indexing and local corrections.

[Focused validation](../validation/2026-10-14-git-snapshot-freshness.md) and
[release status](../RELEASE_STATUS.md) record source and distribution acceptance.
Broader capture coverage and company-host management remain on the roadmap.
