# Mnemion 4.8.1

Large imported files can occupy several search results with different parts of
the same document. Search and context now default to **one result per imported
document**, giving other matching sources room in the result list. The app,
HTTP API, Python/TypeScript clients, agent tools and evaluation runs expose
`max_per_source`: choose a higher limit or `0` for all matching parts.

Candidate selection also gives different documents priority before filling its
existing bounded windows. Grouping uses the standard adapter's source identity,
space and original author. Equal titles alone do not merge memories, and all
stored parts, source evidence and permissions remain available. No re-index or
additional model call is required. See [search controls](../service/retrieval.md).

Evaluations now accept valid bounded excerpts from long sources. Verification
still checks hashes, exact text, Unicode offsets and the original citation
bounds; a narrowed excerpt no longer has to cover the complete original source.
Document limits and grouping results are recorded for reproducible comparisons.

This batch advances the duplicate-file report in
[issue 31](https://github.com/Perseusxrltd/mnemion/issues/31). Default source-age
and archive preferences already exist; stronger current-state ranking, dated
sections and general question quality remain open. See the
[validation record](../validation/2026-10-15-source-grouping.md) and
[complete requirements](../PRODUCT_REQUIREMENTS.md).

There is no database migration after 4.8.0's `017_recovery_directory.sql` and no
model-generation change. A managed server already on 4.8.0 can use its normal
compatible-update policy. Servers on 4.7.1 or earlier still need the
[guarded operator upgrade](../service/managed-upgrades.md) across migration 017.
Desktop updates and their local workspace migrations use the normal native
release gates. [Release status](../RELEASE_STATUS.md) distinguishes source
preparation from public downloads and verified automatic updates.
