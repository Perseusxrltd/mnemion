# Mnemion 4.20.0

Git journals can publish through a repository-specific SSH deploy key. Choose
**SSH · repository deploy key** in the local app, select its private key and
verified host-key file, then approve space publication. Headless hosts and local
agents have the same capability through their existing enrollment controls.

- Explicit `ssh://user@host/repository` addresses support custom ports. SSH uses
  only the selected identity and host pins, without interactive prompts, agent
  fallback, forwarding or user/system SSH command overrides.
- Credential files are checked for private ownership and read through bounded
  handles. Temporary private snapshots avoid reopening mutable source paths.
  Paths with spaces, Unicode, quotes and percent signs work in the real SSH test.
- Receipts and app status identify local, HTTPS and SSH destinations. The legacy
  `remote_git` receipt means acknowledgement by the selected repository. A local
  bare repository's receipt does not verify off-host replication or a full backup.
- Existing HTTPS/local destination fingerprints remain stable. Upgrading does
  not invalidate their publication approvals, spool state or retry indexes.
- Host-key failure and key revocation leave publication pending. Retrying the
  same event remains exact after access is repaired; concurrent writers refetch
  without force-pushing or replacing the other writer's records.

Git and OpenSSH are host prerequisites; this change creates no account or paid
service. Key creation, provider registration and independent recovery custody
remain operator responsibilities. Read [SSH setup](../service/git-journal.md#ssh-deploy-keys-and-host-pins),
[receipt semantics](../service/git-journal.md#save-acknowledgments-and-failures),
[validation](../validation/2026-10-19-journal-ssh.md) and
[publication status](../RELEASE_STATUS.md).
