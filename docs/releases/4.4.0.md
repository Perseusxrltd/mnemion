# Mnemion 4.4.0

Share a locally hosted workspace from **Setup & this device → Remote access**.
Choose a managed ngrok connection or an existing HTTPS proxy, save its address,
and let the app restart the same workspace and check the route. Copy the public
workspace and MCP addresses, create personal invitations, and enable hosted-agent
login and consent from the same setup. The native engine now includes the
matching browser interface and consent-page assets.

Connection failures leave local access available. Mnemion supervises its own
ngrok session, retries with bounded backoff and offers **Check now**. Settings
changes preserve workspace identity and serialize with shutdown and updates.
Equivalent private local commands let authorized operator agents configure and
check access. Saved provider tokens stay in protected operator files and are
never returned in status or links.

The [setup guide](../service/remote-access.md) covers provider limits, token
storage, HTTPS forwarding and recovery. A free ngrok account is supported within
its quotas; using an existing proxy remains an option. The host must be running
and reachable. Independent failover, company hosting/SSO and live acceptance in
each named AI provider remain on the roadmap.

No database migration or memory re-index is introduced. See the
[validation record](../validation/2026-10-15-native-remote-access.md) and
[published release status](../RELEASE_STATUS.md) for source, platform and delivery
evidence. Mnemion remains free.
