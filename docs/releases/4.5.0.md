# Mnemion 4.5.0

This candidate was not published. Its workflow is included in
[4.6.0](4.6.0.md), which corrects the Windows issues found by installed acceptance.

Create encrypted workspace backups from **Setup & this device → Backups**.
Choose a folder, save a recovery key separately, and use manual copies or
scheduled snapshots with more frequent deletion/access ledgers. The desktop
protects scheduled keys using the operating system's credential store and
shows the last successful files, missing copies and failed jobs. When that
store is unavailable, manual backups remain available without saving the key.

Use **Recover a workspace** on the connection screen to inspect a snapshot and
its latest ledger, then restore into a separate local workspace. Recovery
checks both selected files, applies current deletions and access restrictions,
revokes old credentials and creates fresh administrator access. The app can
open the recovered copy after restart and return to the original workspace.
The original files stay in place; external connections require review before
they resume. A recovery copy is independent of the original agent's login.

Backup and recovery jobs serialize with local host changes, shutdown and
automatic updates. Cancellation drains owned processes, private staging avoids
placing cleartext archives in the selected backup folder, and estimated disk
checks precede large writes. Restores also preserve the source database's
timezone so calendar-day session constraints survive a move between hosts.
Windows staging and new recovery folders receive the current account's private
ownership at creation, including elevated sessions. Backup failures appear as
accessible alerts and report their actual error in the installed acceptance check.

The [backup and recovery guide](../service/native-backups.md) covers keys,
schedules, recovery and operator commands. Keep all keys needed by older copies;
there is no key-recovery service. This release keeps every backup. Cloud upload
is provided by the user's chosen folder sync tool, and a locally recorded file
does not prove remote delivery. An out-of-date ledger cannot include later
deletions. Retention controls, recovery-custodian onboarding, company failover
and full agent schedule management remain on the roadmap.

No service schema migration or memory re-index is introduced. The
[validation record](../validation/2026-10-15-native-backup-workflow.md) records
the source checks and desktop walkthrough. The installed pipeline adds backup,
deletion reconciliation, independent recovery and reopening to all six native
targets; publication requires their existing release gates to pass. Consult
the [public release status](../RELEASE_STATUS.md) for actual availability.
Mnemion remains free.
