# Mnemion 4.15.0

Native memories previously stayed in their host database unless separately
exported. This batch adds an optional Git journal for future native changes,
advancing the host-loss report in issue 39.

- An administrator approves a host-registered repository for a writable space.
  Secret checks run before commit; a private local journal is durable before an
  ordinary save returns. Important saves require confirmed Git delivery.
- A dedicated, scoped publisher sends bounded batches on a schedule. It checks
  current permissions and memory state, preserves unrelated repository files,
  retries concurrent commits and never force-pushes.
- Studio shows destination approval, pause/repair controls, pending counts and
  the last confirmed commit. Python, TypeScript, CLI and MCP expose the same
  controls; local enrollment remains a host-operator command.
- Complete journal inventories replay as stable source memories. Repeated
  records deduplicate; deletions and quarantines are reconciled before import.
  Missing catalog records and incomplete histories fail visibly.
- Database recovery pauses publication and suppresses withdrawn pending text.
  Host restoration does not activate an imported scanner or Git configuration.
- Pinned local models reuse complete caches without network requests. Missing
  files download directly from their pinned revision, avoiding repository-listing
  rate limits on shared networks. Checksum verification and vector identities
  remain unchanged; no reindex is needed.

Migration 022 adds opt-in policy/event tables without changing existing memory
rows or enabling a destination. After-commit failures return a retryable error;
clients must reuse the original idempotency key. The app hides incompatible
controls when connected to servers older than 4.15.0.

Git history retains published text after deletion. This feature is unsuitable
for content requiring complete erasure from external history. It does not
backfill existing memories or restore native accounts, grants and database IDs.
Librarian folding/archival, complete app enrollment, large-history scaling and
live-provider acceptance remain open; issue 39 is not closed by this batch.
