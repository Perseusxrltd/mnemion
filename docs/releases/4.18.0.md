# Mnemion 4.18.0

**Not published.** Its new installed Git-setup check caught desktop connections
dropping the server version and hiding supported features on all six targets.
[4.19.0](4.19.0.md) carries these changes with the metadata fix and retains the
acceptance check. The frozen 4.18 source is unchanged.

Desktop host owners can register Git journal destinations directly in Studio.
Choose an existing HTTPS repository, branch and folder for the selected space;
the app saves private settings, drains the local service and reopens it. There
is no registry-file editing or environment-variable setup for this path.

- Host registration remains separate from the administrator's approval to publish
  a space. Registration alone makes no Git request and publishes no memories.
- Each space gets its own private queue. Repository choices cannot supply a host
  path, executable scanner or credential. Git uses the OS account's existing
  credential manager; its installation and sign-in remain prerequisites.
- Current workspace and settings revisions protect concurrent edits. Changing
  the destination requires fresh publication approval and retains queued records.
  Previously published history stays in its original repository.
- Existing operator-managed registries are preserved. Removing a registration
  retains queue files; explicit repair preserves the damaged configuration.
- Local agents use the same `local.journal` desktop operation, including restart,
  current-workspace and unsaved-edit safeguards. Remote memory keys gain no host
  configuration authority.
- The installed-app acceptance flow now registers a synthetic destination through
  the actual UI, verifies the controlled restart and checks that publication is
  still unapproved. It makes no Git network call.

This advances the remaining onboarding work in issue 39. Provider sign-in,
guided remote-host enrollment, old-buffer reconciliation, backfill, direct writable
reconstruction and large-history acceptance remain open. Host registrations and
Git credentials still need independent recovery custody; database restoration
does not silently enable publication or recreate those host settings.
