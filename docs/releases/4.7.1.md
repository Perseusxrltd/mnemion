# Mnemion 4.7.1

Desktop backups now offer opt-in retention, a private inventory and reviewed
cleanup in both the app and the local agent interface. Keep-all remains the
default. Cleanup protects two verified snapshot/ledger pairs, the newest access
ledger, files belonging to other keys and untracked files. The local interface
now exposes 21 operations. [Retention evidence and limits](../validation/2026-10-15-backup-retention.md)
include actual Windows file operations, PostgreSQL recovery and the source app.

Native Linux database ownership and RAM accounting remain correct after clock
adjustments. A failed database shutdown blocks desktop automatic-update
readiness so an installer does not race a still-running workspace.

Managed Linux and macOS servers with automatic updates enabled can now accept
newer minor releases in the same stable major series when their database
migrations and model generations match. Previously, a version such as 4.4.0
required operator intervention from 4.3.x even with no schema or model change.
Paused installations remain paused.

The updater still verifies the publisher, downloaded and installed bytes, live
model configuration and database backup before stopping the service. Major
versions, schema changes and different model generations remain blocked from
automatic application. A failed new runtime recovers using the existing live
database, preserving writes accepted before the failure.

An existing staged package is evaluated against the current runtime and policy.
An older cached eligibility decision cannot permanently block a compatible
minor release or authorize an incompatible change. Operator status exposes the
version policy, and pending-update diagnostics follow the same rules.

Temporary supervisor timeouts now retry within the existing process-transition
deadline. Each reconnection verifies the instance, and repeated named start/stop
requests safely handle a lost acknowledgement. Identity failures, missing roles
and failed worker readiness still stop the update.

The [validation record](../validation/2026-10-15-compatible-minor-updates.md)
includes signed-manifest and scheduling checks and a real installed minor
upgrade followed by failed-update recovery. The [server update guide](../service/managed-updates.md)
explains the policy. Older patch-only installations may need one explicit
[operator upgrade](../service/managed-upgrades.md) to reach this version.
Desktop delivery and publication remain tracked in [release status](../RELEASE_STATUS.md).

No database migration or memory re-index is introduced. Company maintenance
windows, fleet policy, Windows-hosted services and automatic schema migrations
remain on the roadmap. Mnemion remains free.
