# Mnemion 4.7.0

This source batch was not published. Its features are included in
[4.7.1](4.7.1.md), together with the managed-server restart correction.

Local backups can now retain a chosen number of recovery points. **Keep all
copies remains the default**, including for existing schedules. In **Setup &
this device → Backups & recovery**, choose limits for full snapshots and recent
access ledgers, review recorded files and their sizes, and explicitly confirm
an immediate cleanup. Limited schedules also clean up after successful full
backups. Each batch considers at most 200 older files.

Cleanup preserves paired access ledgers, the latest recorded recovery files,
other encryption keys and untracked files. Before removing anything, it checks
two retained snapshot/ledger pairs and the newest access ledger against the
bytes authenticated at capture. Changed, missing or unavailable retained points
block removal. A replaced backup folder does not inherit deletion authority.
The inventory works while the database is stopped and does not need the recovery
key. Cancellation leaves an explicit result for completed removals.

Local agents have the same inventory and cleanup controls through
`backup.inventory` and `backup.prune`, bringing the private desktop catalog to
21 operations. Manual cleanup requires the current settings revision, reviewed
plan token and confirmation. Protected recovery keys are never returned.
See the [backup guide](../service/native-backups.md) and
[local operator guide](../service/desktop-operator.md).

This version also fixes local database ownership checks when Linux adjusts its
boot-time estimate. RAM accounting and shutdown use the existing process identity
based on boot ID and process start ticks. A failed engine shutdown remains
visible and blocks automatic-update readiness until the workspace can stop
successfully; closing the engine process alone is no longer treated as proof
that the database stopped.

The [retention validation](../validation/2026-10-15-backup-retention.md) includes
actual Windows file operations, PostgreSQL recovery and a source Electron
app/agent walkthrough. The [clock and shutdown validation](../validation/2026-10-15-native-clock-shutdown.md)
reproduces the ownership error with a real database and verifies clean teardown.
These source checks do not replace installed acceptance on all six targets.
See [release status](../RELEASE_STATUS.md) for verified public availability.

There is no service schema migration or memory re-index. Cloud upload verification,
permanent per-file cleanup audit history, independent host takeover and company
recovery policy remain on the roadmap. Local cleanup may propagate deletions
through your chosen storage application. Mnemion remains free.
