# Mnemion 4.46.27

Native and Python product telemetry now use only the TLS certificate authorities
bundled with the release. Route version 2 allows at most two public CA
certificates, each at most 4 KiB, supporting a bounded overlap during issuer
rotation. Missing or invalid trust prevents connection. Minimum TLS 1.3,
certificate/hostname verification, literal-address routing and the existing
consent, review, deadline and budget checks remain mandatory. Browser TLS is
unchanged; no CA digest is added to reports.

[Source validation](../validation/2026-10-26-telemetry-scoped-trust.md) passed
78 distinct Python cases and 54 checks in the actual local Electron binary
running Node mode, with no Electron skips or failures. Ruff and the Electron
build passed. Real TLS checks cover explicit trust, issuer overlap, refusal of
ambient-only trust and the existing cancellation/privacy boundaries. Initial
fixture-name lint failures and the synthetic issuer-collision failure are
retained with their fixture-only corrections; the corrected negative case was
also checked independently without counting it twice.

A [Windows ARM release-test correction](../validation/2026-10-26-telemetry-scoped-trust.md#windows-consent-test-deadline-correction)
separates the consent/generation assertion from optional measurement-admission
timing. It obtains a new real policy/permission snapshot before each test action;
production deadlines, permissions and measurement behavior are unchanged. A
75 ms delayed real read reproduced the original assertion locally, supporting a
plausible scheduling cause without measuring the original Windows timing. The
corrected consent test and unchanged late-admission test both passed under that
hook, adding two distinct local Electron cases (**56 total**). The original
Windows failure and downstream missing scan receipt remain retained; hosted
Windows ARM and new-release acceptance are still pending.

The TLS change addresses a concrete first-use allocation hypothesis. No RSS saving
or resource-gate pass is established. The previous six-case resource failure
and rejected SQLite experiments remain retained; one fixed current-source
follow-up is planned after integration. All 66 requirements and the 2 MiB /
0.5% limits remain unchanged.

V08 remains **Building and inactive**. Collection is unavailable, destination and
route address are null, and the authority list is empty. Production certificate
selection/rotation, provider privacy, whole-wire cost and installed-platform
qualification remain open. Publication and actual PC/VPS upgrades require their
separate evidence; current availability belongs to
[release status](../RELEASE_STATUS.md).
