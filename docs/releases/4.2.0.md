# Mnemion 4.2.0

People can join a workspace with an expiring invitation, choose their own login
and password, and manage individual device sessions in **Account & sessions**.
Administrators set explicit space permissions, issue invitations or password
resets, and revoke sessions. A shared administrator key is no longer required
for this personal sign-in flow. Existing application and recovery keys remain
independently controlled.

Desktop remembering uses the operating system's protected credential store.
Browser remembering uses the workspace's HTTPS origin and protected cookies.
Rotating session credentials stay outside browser local storage and the desktop
renderer. Lost refresh responses require signing in again, and browser tabs
coordinate refresh and sign-out. The desktop waits for its local host to be
ready before restoring a remembered person and verifies the same workspace.

The reviewed agent catalog grows from 87 to **100 operations**. Private CLI
input and result files let authorized agents handle login, invitations and
refresh without printing credentials. Session and invitation administration
retain the existing tenant, administrator and space checks. Password work,
attempt history and active-session counts have explicit bounds.

**Service migration 015 is required.** Follow the backup and guarded upgrade
procedure for separately hosted services; the automatic service updater does
not silently apply an incompatible schema change. A desktop update cannot
upgrade a remote server. Hosted-agent OAuth consent and complete company SSO
onboarding remain on the roadmap.
