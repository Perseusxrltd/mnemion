# Mnemion 4.1.7

Managed service update checks now catch up after a suspended cloud host or
laptop resumes. A frozen monotonic clock could previously stretch a six-hour
check across many more hours of real time. Either elapsed wall time or elapsed
monotonic time now makes the check due, so a clock correction in either direction
cannot postpone it indefinitely. A short retry floor prevents clock jumps from
causing repeated immediate network requests.

Host agents and administrators can see `next_check_at`, `overdue` and
`last_attempt_at` in `mnemion-service updates status`. The recorded deadline
includes the actual scheduling jitter. Older records without a deadline are
explicitly marked `schedule_estimated`.

The existing update pause preference, connector operation leases, signed
manifests, replay protection, backup checks and compatible-schema requirement
remain enforced. This fixes [issue 33](https://github.com/Perseusxrltd/mnemion/issues/33).
No database migration or model download is required. The managed host must
receive the patch; updating a desktop does not update a separately hosted server.

See the [managed update guide](../service/managed-updates.md) and
[source validation](../validation/2026-10-13-managed-update-schedule.md).
