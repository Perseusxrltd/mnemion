# Mnemion 4.46.36

Capture enrollment now rejects a conflicting authorization if another request
claims the same grant ID for a different source during enrollment. The stored
source, device key and approved policy are checked after insertion, and the
existing authorization remains with its original source.

Applications and agents can distinguish fresh capture changes from repeated
requests. Concurrent revocations use the current state under the source lock.
Studio's policy approval and device revocation buttons use typed client methods,
and the agent command layer preserves replay metadata without changing which
requests may be retried.

This release also includes the earlier first-time telemetry disclosure and
update-verification timing improvements. Telemetry remains in development and
collection is disabled in this release.

The capture batch qualified 106 distinct Python tests, 22 SDK tests and 49
Studio/policy source tests; SDK, frontend and Electron builds passed. See the
[capture correction and evidence](../validation/2026-10-27-telemetry-capture-admin.md),
[setup disclosure](../validation/2026-10-27-telemetry-setup-disclosure.md),
[update verification](../validation/2026-10-27-telemetry-update-verification.md)
and [remaining telemetry acceptance](../validation/2026-10-27-telemetry-acceptance-ledger.md).
