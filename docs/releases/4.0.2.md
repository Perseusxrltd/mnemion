# Mnemion 4.0.2

This product v1 hotfix improves remote-agent setup, MCP authentication and
concurrent memory requests. Published desktop targets remain Windows x64 and
macOS/Linux on x64 and ARM64. Windows ARM64 automatic relaunch remains a release
gate. Downloads and version-specific notes are selected automatically on
[the product page](https://www.perseusxr.com/mnemion).

## Fixes

- **Issue 5:** authenticate every HTTP MCP request, including initialization and
  tool discovery. Reject missing, malformed, duplicated, invalid and revoked
  keys without using an owner/stdio fallback. Bound gateway capacity and
  authentication time; retain host/origin protection on public listeners.
- **Issue 10:** serve `/mcp` and `/v1/` on the same port by default. A single HTTPS
  proxy or existing tunnel can expose both. Configure `--public-url` with its
  exact origin. Internal tools use the same API authorization/validation through
  ASGI, without consuming another listener slot or deadlocking on loopback HTTP.
  `--no-mcp` and the separate-port gateway preserve operator choice.
- **Issue 9:** explain an invalid recall scope explicitly: select non-empty
  `space_ids`, or use `space_ids: []` with `all_accessible: true`, never both.
  Keep HTTP 422 and the existing error contract; do not silently broaden access.
- **Issue 12:** serialize inference with a bounded queue of 16 waiting calls and
  a 2-second admission wait by default. Expose bounded operator settings, send
  `Retry-After` with overload responses, and honor retry hints in both SDKs for
  safe/idempotent operations. Model activations are not multiplied by callers.
- **Issue 16:** describe all core MCP tool fields and return compact structured
  tool errors with retry guidance. Omit raw rejected values and tracebacks.
  Existing core tools and legacy aliases retain their names and permissions.
- Keep product-page downloads, release versions, notes and published metadata
  synchronized from verified GitHub release assets. An authenticated release
  webhook expires page caches; a scheduled reconciliation updates the checked
  manifest on `main`. The roadmap links directly to maintained repository docs.

## Upgrade and compatibility

No database migration, embedding-generation change or Obsidian format change is
introduced. Existing identities, grants, keys, source spaces and memory revisions
remain valid. The inference queue has bounded resource use; larger queues do not
guarantee a particular throughput and API/worker model caches remain separate.

**Update the memory server to receive the API/MCP fixes.** Desktop automatic
updates replace Studio, not a separately deployed service or its database.
Source installations require a release checkout, locked dependencies and a
supervisor restart; follow [deployment](../service/deployment.md) and
[recovery](../service/recovery.md). Managed source-server auto-updates and
non-systemd supervision remain open issues 6/11. For an existing HTTPS endpoint,
set its origin with `MNEMION_PUBLIC_URL` or `serve --public-url` before restarting.

Windows first installation may show an unknown-publisher prompt while SignPath
approval is pending; subsequent updates verify the independent publisher key.
Mac builds require macOS 13+, use ad-hoc signing and independently signed Sparkle
updates, and may need first-launch Privacy & Security approval. Linux AppImage
updates need a writable installation; DEB updates use the package administrator.
See [desktop updates](../service/updates.md).

## Validation and remaining work

Release checks exercise real PostgreSQL authorization, API/MCP on one listener,
modern and legacy MCP initialization, revocation and invalid headers, scope
diagnostics, privacy-preserving errors, SDK retries and bounded inference. A
ten-caller queue test verifies serialization with a controlled synthetic workload;
it is not a production throughput benchmark. Publication also requires native
installation/update/relaunch checks for every selected platform, product checks
on Python 3.12–3.14, package consistency, and verified immutable assets.

Remaining work includes Windows ARM64 relaunch, a public-artifact upgrade
rehearsal beyond private signed fixtures, OAuth/ChatGPT sign-in, managed server
updates, full discoverable agent administration, reduced worker/API RSS, source
sync triggers, author-deletion policy and natural-language retrieval evaluations.
See the [roadmap](../ROADMAP.md), [validation report](../validation/2026-10-10.md)
and [issue queue](https://github.com/Perseusxrltd/mnemion/issues).
