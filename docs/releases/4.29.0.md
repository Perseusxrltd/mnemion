# Mnemion 4.29.0

Large native journals can now be recovered through the app in resumable uploads.
The complete input can contain up to 2 GiB, one million physical records and
100,000 memory identities. A lost connection or app restart retains progress;
the original files are checked before sending the remaining bytes.

The complete history is reviewed before approval. Withdrawals and quarantines
run first, then recovery saves bounded batches. Changed destinations stop the
affected batch and require fresh review. Local edits, permanent withdrawals and
already-restored batches remain protected. Cancellation stops future work and
queues private staging cleanup without undoing accepted memories.

Studio shows upload/review/restoration progress, saved recoveries, Pause/Resume,
paged decisions and explicit batch approval. Completed or paused durable recoveries
do not leave the desktop update guard marked as an unsaved form; active requests
and unsubmitted journal selections still protect restarts. Python, TypeScript and seven private
agent operations expose the same workflow. Staging uses bounded PostgreSQL data,
per-administrator capacity limits and automatic expiry. The existing small API
remains compatible. No model call or paid dependency is added.

The [recovery guide](../service/journal-recovery.md) documents limits, private
staging retention, transport verification, API/SDK controls and backup boundaries.
[Validation](../validation/2026-10-20-resumable-journal-recovery.md) records actual
browser interruption/resume, protected batch recovery, SDK parity and migrations.
Migration 028 is additive and follows the normal protected host upgrade process.
The roadmap and product requirements record the advance without inflating full
scope: **17/64 (26.6%)** remain fully shipped. Issues 3, 4 and 18 retain their
real-provider acceptance gates. Public installers and automatic updates follow
the existing platform release gates.
