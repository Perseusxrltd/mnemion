# Mnemion 4.2.4

Managed Linux/macOS hosts can move across a schema or minor-version boundary
with `updates plan` and an exact-version `updates upgrade --allow-migration`.
The command stages and authenticates the new runtime, verifies a database backup,
drains the service, applies the checked migrations and restarts the API, worker
and updater. It retains existing keys and already enrolled source identities.
The [managed upgrade guide](../service/managed-upgrades.md) includes a bridge for
older 4.1.x command-line tools, connector handling and journaled recovery.

This path does not require a second running service or another loaded embedding
model. If migration has not committed, failure can restore the old runtime. If
migration committed and startup fails, the journal supports a forward resume;
database backups are never restored automatically over potentially accepted
writes. Current migration checksums, ordered history, exact signed packages and
unchanged model generations remain required.

`updates status` now shows the authenticated pending version, concrete blocking
reasons and the upgrade guide independently of a stale last-check record. A
command waiting behind another updater or source scan reports `deferred`, a retry
hint and exit status 75. Recovery pins its backup and both runtime endpoints.
An intentionally paused updater no longer prevents checking API/worker readiness
during the guarded cutover. This addresses the managed-host blocker in issue 36.

Repository maintenance now collects issue changes, build outcomes and failed job
steps automatically. The [maintenance board](../MAINTENANCE_STATUS.md) refreshes on
GitHub events and the existing schedule; unchanged observations avoid extra
commits. The release integration script handles normal pushes and generated
metadata races, keeping a clean local main worktree current. It stops for actual
incoming source changes and never rewrites a published release or frozen source.

The full automated build, signature, publication, website and public-update
pipeline remains in force. [Focused validation](../validation/2026-10-14-managed-upgrade-automation.md)
records source and real process/database checks; the
[release status](../RELEASE_STATUS.md) retains public delivery evidence.

No production database migration is added after 015. Desktop updating retains
the existing Windows, macOS and Linux behavior. Windows-hosted services,
containers, fleet maintenance policy, model changes and major-version upgrades
remain separate deployment work. The [full requirements](../PRODUCT_REQUIREMENTS.md)
remain intact.
