# Mnemion 4.8.0

Administrators can keep host and recovery references available independently of
the original agent or memory server. **Recovery directory** adds host/operator
entry points, backup/ledger/source locations, independent contacts and a
downloadable encrypted HTML kit in the app and browser.

- Current administrator checks, tenant isolation, revision conflicts and audit
  events protect the shared directory. Its metadata stays outside memory search,
  source ingestion, embeddings and automatic model context.
- Remembered desktop administrator connections retain a dated, OS-protected
  copy. **Details & recovery** reads it without reconnecting. Existing credential
  formats remain compatible, and an unavailable older server does not prevent login.
- The kit opens offline or from independently controlled HTTPS hosting. It uses
  a separately held passphrase and contains directory references; saved workspace
  logins and database backups are not added. The same viewer is available through
  `mnemion-service recovery-kit`, including private control-CLI result files.
- Agents and SDK users receive `recovery.directory` and `recovery.configure` with
  the same authorization and concurrency rules as the app.

See the [guide](../service/recovery-directory.md) and
[focused validation](../validation/2026-10-15-recovery-directory.md).
Native package, public-update and publication results are retained automatically
in [release status](../RELEASE_STATUS.md). Source validation does not imply that
this candidate has already been published.

This release adds checked migration **017**. Back up the database and current
access/deletion ledger before a separately hosted server upgrade; use the
[guarded upgrade procedure](../service/managed-upgrades.md). A server's
automatic policy does not apply schema changes merely because a desktop update
is available. Older services keep serving their existing memory API while the new
directory page explains the required server upgrade.

Host restart/delegation, independent backup delivery verification, company SSO,
recovery-custodian policy and safe replica takeover remain on the full roadmap.
Registering a host or Git mirror does not grant host access or create a complete
workspace backup.
