# Mnemion 4.46.35

The Python telemetry sender now limits its kernel receive buffer before connecting. An oversized response could previously exceed the reserved network allowance before the application rejected its headers. If the operating system cannot apply or verify the buffer limit, the optional attempt stops before connecting and clears its lease while preserving the spent reservation.

The isolated Linux burst check measured 123,053 frame bytes before the correction and 23,110 afterward, against the unchanged 65,536-byte reservation. All 32 Python transport checks passed, including four new operating-system refusal cases. The original failure and both measurements are retained.

This is a Python transport correction. Other platforms and transports, retransmissions, resource budgets, installed delivery and hosting privacy remain unqualified. Production telemetry collection remains unavailable; V08 is still Building.
